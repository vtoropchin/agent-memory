# Задача 13.1 — Сущность «техдолг» (`kind = "debt"`)

**Статус:** ✅ выполнена
**Этап:** 13 (Сущность техдолга, DESIGN.md §14 Этап 13) · **Область:**
`internal/memory` (`types.go`), `internal/memory/recall`, `internal/config`,
`internal/mcp` (`schema.go`, `instructions.go`), `cmd/memo` (генерируемые скиллы
`memo`/`memo-bootstrap`), `cmd/memo/web`
**Зависимости:** нет.

## Контекст

Найденный по ходу разработки техдолг сейчас некуда системно записывать: он либо
теряется, либо оседает произвольной строкой в `tasks/README.md` («Отклонённые
идеи») или в комментарии кода. Решение (согласовано с пользователем, см.
DESIGN.md §2/§4/§8/§11/§12/§13/§14): техдолг хранится в `memo` наравне с
остальной памятью — новый `kind = "debt"`, четвёртый тип рядом с
`semantic`/`episodic`/`procedural`. **Не** отдельная таблица, **не** отдельные
MCP-инструменты, **не** отдельная подкоманда CLI в этой итерации.

Ключевые решения:

- Схема не мигрирует: `kind` — TEXT без CHECK, одинаково в SQLite и PostgreSQL.
- Статус долга — не отдельное поле. Открыт = живая запись; закрыт = существующий
  тумстоун через supersede: `memory_forget(id, replaced_by=<id записи о фиксе>)`;
  если долг снят без фикса — `memory_forget` без `replaced_by`.
- Recall: долг входит в дефолтную выдачу, но выводится отдельной секцией брифа
  `Tech debt (debt)` (порядок секций: Facts → How-to → Tech debt → Recent
  context) и получает понижающий множитель итогового скора — новый
  `[recall] debt_weight` (дефолт `0.6`, допустимый диапазон `(0, 1]`, `0`/поле не
  задано → дефолт). В explain-трассе множитель виден отдельным полем
  `KindFactor`: инвариант «сумма слагаемых == Final» становится «(сумма
  слагаемых) × KindFactor == Final».
- Maintenance: `Decay`/`Consolidation` по коду работают только с `episodic` —
  долг не затухает и не консолидируется, живёт до явного закрытия. Dedup-sweep
  уже группирует кандидатов по паре `(scope, kind)` — долги дедуплицируются
  только между собой, изменений тут не требуется. TTL/`ExpireSweep` применимы к
  записи любого `kind`, включая `debt`, без изменений.
- Поверхности этой итерации: MCP (enum `kind`, инструкции сервера, генерируемые
  `memo init` скиллы), web-морда (бейдж kind + счётчик открытых долгов на
  дашборде). Подкоманда `memo debt` в CLI **сознательно не делается** — сущность
  полностью доступна через уже существующие `memory_save`/`memory_recall`/
  `memory_forget` и web-фильтр по kind.

## Что сделать

### Подзадача A — ядро: kind, recall, config

- `internal/memory/types.go`: константа `memory.KindDebt = "debt"`.
- `internal/config/config.go`: `RecallConfig.DebtWeight float64` (`toml:"debt_weight"`),
  дефолт `0.6` в `Default()`, валидация — `0` трактуется как «не задано» (откат на
  дефолт в `recall.New`), явное значение вне `(0, 1]` — ошибка `Load` (тот же
  принцип, что у `MaintConfig.Durations`).
- `internal/memory/recall/recall.go`:
  - новая секция брифа `Tech debt (debt)` между `How-to (procedural)` и
    `Recent context (episodic)` (переменная `sections`);
  - в `rank()` — множитель `debt_weight` на `final` для `kind=debt` (`1` для
    остальных `kind`), поле `Explain.KindFactor` рядом с уже вычисленными
    слагаемыми, `formatExplainLine` учитывает его в выводимой формуле.
- `internal/memory/maint`: только проверить (без изменений), что
  `ListEpisodicForDecay`/`ListEpisodicForConsolidation` и `groupForDedup`
  (группировка по `(scope, kind)`) уже исключают/корректно обрабатывают `debt` —
  зафиксировать в отчёте, что изменений не потребовалось, либо внести точечную
  правку, если найдётся расхождение.

### Подзадача B — MCP-поверхность

- `internal/mcp/schema.go`: `kindEnum` → `["semantic", "episodic", "procedural", "debt"]`,
  описание поля `kind` в `saveInput`/`recallInput` (jsonschema-тег) упоминает `debt`.
- `internal/mcp/instructions.go` (`buildInstructions`): абзац про конвенцию
  `kind=debt` — что писать в `content` (что не так + где + почему отложено +
  критерий закрытия), `importance` = приоритет, `tags` = область, закрытие через
  `memory_forget`.
- `cmd/memo` — генерируемые скиллы `memo` и `memo-bootstrap` (шаблоны в
  `bootstrap_skill.go`/аналогичных файлах): упомянуть `kind: debt` там, где
  перечисляются типы памяти.
- CLI-флаги `memo recall -kinds` / `memo save -kind` (`cmd/memo/cli.go`) —
  описания флагов включают `debt` в перечень типов.

### Подзадача C — web-морда

- `cmd/memo/web/app.js`: бейдж kind `debt` (цвет/подпись, по образцу
  `semantic`/`episodic`/`procedural`) на дашборде статистики — тот же чип
  `stats.byKind`, что и у остальных kind, даёт и счётчик открытых долгов, и
  toggle-фильтр по клику; отдельная плашка-счётчик не заводится (дублировала
  бы чип и висела нулём при отсутствии долгов — снята по code review).

## Границы

- Схема БД/миграции не трогать — `kind` уже TEXT без CHECK.
- `memo debt` как отдельная CLI-подкоманда — не делать (см. Отложено ниже).
- Content/kind правки записи из web по-прежнему не делаются (DESIGN.md §12,
  «Суженный инвариант оффлайновости» / write-инвариант web-морды) — долг
  заводится только через MCP/CLI. Закрыть долг из web можно (DELETE
  /api/memories/{id} → `handleForgetMemory` → `Writer.Forget`), но только
  self-тумстоуном, без `replaced_by` — указать запись-замену из web нельзя.
  Отложено осознанно: под эту итерацию отдельный UI для `replaced_by` не
  нужен, closure с привязкой к фиксу делается через MCP/CLI.

## Тесты

- `internal/config`: `RecallConfig.Validate` — `0` ок (дефолт), значение в
  `(0, 1]` ок, вне диапазона — ошибка.
- `internal/memory/recall`: новая секция брифа появляется для `kind=debt`;
  `debt_weight` действительно понижает `final` (сравнение с/без записи `debt` в
  выдаче); `Explain.KindFactor` равен `1` для не-`debt` и `debt_weight` для `debt`,
  инвариант с учётом `KindFactor` держится.
- `internal/mcp`: `schema_test.go` — `kind: "debt"` проходит валидацию схемы
  `memory_save`/`memory_recall`.

## Критерий приёмки

- `CGO_ENABLED=1 go build -tags sqlite_fts5 ./...` и
  `CGO_ENABLED=1 go test -tags sqlite_fts5 -count=1 ./...` зелёные.
- `memory_save(kind="debt", ...)` создаёт запись; `memory_recall` без фильтра по
  kind выводит её отдельной секцией `Tech debt (debt)` с пониженным относительно
  facts/how-to влиянием на попадание в бюджет; закрытие через
  `memory_forget(id, replaced_by=...)` убирает её из recall.
- Web-морда показывает бейдж `debt` и счётчик открытых долгов.
- DESIGN.md согласован с реализацией (§2/§4/§8/§11/§12/§13/§14 без противоречий).
