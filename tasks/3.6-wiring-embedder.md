# Задача 3.6 — Связка Embedder в memoryd и конфиге

**Статус:** ⏳ ожидает 3.1–3.5
**Этап:** 3 (Embedder + гибрид) · **Пакеты:** `cmd/memoryd`, `internal/config`
**Зависимости:** 3.1–3.5

## Контекст

DESIGN.md §9, §13. После 3.1–3.5 есть `embed.Ollama`, Writer/Recaller принимают Embedder,
`maint.Reindexer` умеет CheckAndReindex. `cmd/memoryd` всё ещё передаёт `embed.NewNoop()`.

## Что сделать

1. `cmd/memoryd/main.go`: фабрика Embedder по конфигу (симметрично фабрике Reasoner из 2.4):
   - `provider == "noop"` → `embed.NewNoop()`.
   - `provider == "ollama"` → `embed.NewOllama(ctx, cfg.Embedder.BaseURL, cfg.Embedder.Model)`;
     ошибка (ollama недоступен / модель не подтянута) → предупреждение в stderr и откат
     на Noop (деградация §15 — сервер стартует, recall на чистом FTS5).
   - Неизвестный provider → ошибка при старте (fail fast).
   Полученный Embedder передать в конструкторы Writer и Recaller.
2. При Embedder ≠ Noop: после старта запустить в горутине
   `maint.NewReindexer(store, embedder).CheckAndReindex(ctx)` с логом результата
   (Reindexed/Embedded/Failed) в stderr. Горутина не должна блокировать старт MCP-сервера
   и должна завершаться по тому же ctx, что и сервер.
3. Обновить `config.example.toml`: секция `[embedder]` с комментариями (noop/ollama,
   base_url, model, автоопределение dim, поведение при недоступном ollama).
4. Если фабрика выделена в функцию — табличный тест (noop / ollama недоступен → Noop /
   неизвестный provider → ошибка). Для «ollama доступен» использовать httptest.

## Границы

Не трогать: `embed`, `store`, `write`, `recall`, `maint`, `mcp` — только связка.

## Критерий приёмки

- Билд чист; `CGO_ENABLED=1 go test -tags sqlite_fts5 -count=1 ./...` зелёный целиком.
- `provider="noop"`: поведение как раньше. `provider="ollama"` без ollama: предупреждение,
  сервер работает на FTS5.
