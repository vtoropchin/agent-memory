# Задача 3.1 — Ollama-Embedder

**Статус:** ⏳ ожидает
**Этап:** 3 (Embedder + гибрид) · **Пакет:** `internal/memory/embed` · **Зависимости:** нет

## Контекст

DESIGN.md §9: дефолт — `bge-m3` через ollama (мультиязычный: факты на русском, код на
английском); `dim` не хардкодится — определяется пробным эмбеддингом при старте; эмбеддинг —
чистая функция от `(model, text)`, кэшируем по `sha256(model+text)`. Интерфейс `Embedder`
уже есть в `internal/memory/embed/embed.go` (Noop — образец стиля).

## Что сделать

1. Новый файл `internal/memory/embed/ollama.go`:
   - Тип `Ollama`: httpClient (`*http.Client`, таймаут 30s), baseURL, model, dim.
   - Конструктор `NewOllama(ctx context.Context, baseURL, model string, opts ...OllamaOption)`:
     пустые baseURL/model → ошибка. Опции `WithHTTPClient`. В конструкторе — **пробный
     эмбеддинг** одного короткого текста: заодно проверка, что ollama жив и модель
     подтянута; из ответа берётся `dim`. Ошибка → конструктор возвращает ошибку
     (откат на Noop делает вызывающий — задача 3.6).
   - `Embed(ctx, texts)`: POST `{baseURL}/api/embed`, JSON `{"model": ..., "input": [...]}`,
     ответ `{"embeddings": [[...], ...]}`. Не-2xx / число векторов ≠ числу текстов → ошибка.
     Пустой texts → пустой результат без запроса.
   - Кэш: `map[string][]float32` под `sync.RWMutex`, ключ `sha256(model + "\x00" + text)`.
     В `Embed` сначала собрать хиты из кэша, в ollama слать только промахи, результат
     положить в кэш. При превышении 10000 записей — очистить кэш целиком (простая
     стратегия, комментарий об этом).
   - `Model()`, `Dim()` — из полей. `var _ Embedder = (*Ollama)(nil)`.
2. Тесты `ollama_test.go` через `httptest.Server`: пробный эмбеддинг в конструкторе
   (dim определился), успешный батч, кэш (сервер считает вызовы: повторный Embed того же
   текста не ходит в сеть; смешанный батч хит+промах шлёт только промахи), не-2xx,
   несовпадение количества векторов, отмена контекста, недоступный сервер в конструкторе.
   Никаких живых вызовов ollama в тестах.
