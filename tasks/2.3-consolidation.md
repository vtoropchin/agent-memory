## Контекст

DESIGN.md §11: consolidation — кластер похожих episodic → один semantic, старые помечаются
`superseded_by`. Планировщик джобов — Этап 4; сейчас нужна только вызываемая доменная
операция + тесты. Reasoner Noop возвращает `"", nil` — это сигнал «пропустить» (деградация §15).

## Что сделать

1. Расширить интерфейс `Store` (store.go) методом
   `ListEpisodicForConsolidation(ctx, olderThan int64, limit int) ([]Memory, error)`:
   episodic с `created_at < olderThan`, без `superseded_by`, сортировка scope → created_at;
   `limit ≤ 0` — без лимита. Реализация в sqlite.go (с tags/links, по образцу существующих
   выборок) + тест. В комментарии сослаться на DESIGN §11.
2. Новый пакет `internal/memory/maint`, файл `consolidate.go`:
   - `Consolidator` (Store, `reason.Reasoner`, `*write.Writer`), конструктор `NewConsolidator`.
   - `Consolidate(ctx, olderThan time.Duration, batchLimit int) (ConsolidateResult, error)`:
     выборка → группировка по scope → для каждой группы промпт (пронумерованный список
     id+content; строго JSON-массив `[{"content","summary","tags","source_ids"}]`; обобщать
     повторяющиеся эпизоды в устойчивые semantic-факты; одиночные эпизоды не включать;
     язык фактов = язык исходников; без markdown-обёртки).
   - Парсинг ответа (срезать возможные ```-ограждения). Ошибка/пустой ответ (Noop!)/
     невалидный JSON → группу пропустить в `Skipped`, не падать.
   - Валидный факт: `Writer.Save` (kind=semantic, scope группы, importance 3,
     source="consolidation", tags из ответа), затем `store.Supersede(sourceID, newID)`
     для каждого source_id из входной группы (чужие id молча пропускать).
   - `ConsolidateResult{Scanned, Created, Superseded, Skipped int}`.
3. Тесты с in-memory sqlite и фейковым Reasoner: успех (created+superseded, старые выпадают
   из recall/SearchLexical); невалидный JSON → Skipped, база не тронута; Noop → Skipped;
   свежие записи не выбираются; чужой source_id игнорируется.
