# Задача 4.3 — Планировщик maintenance-джобов

**Статус:** ⏳ ожидает 4.1, 4.2 (использует также Consolidator из 2.3 и Reindexer из 3.5)
**Этап:** 4 (Maintenance) · **Пакеты:** `internal/memory/maint`, `cmd/memoryd`, `internal/config`
**Зависимости:** 2.3, 3.5, 4.1, 4.2

## Контекст

DESIGN.md §11 (джобы), §13 (`[maint] decay_interval = "24h"`, `consolidate_after = "168h"`).
`consolidate_after` — это ВОЗРАСТ episodic для консолидации, не интервал запуска.
Все операции уже существуют как вызываемые методы: `Consolidator.Consolidate`,
`Reindexer.CheckAndReindex`, `Decayer.Decay`, `DedupSweeper.Sweep`.

## Что сделать

1. Новый файл `internal/memory/maint/scheduler.go`:
   - Тип `Scheduler`, собирающий джобы; конструктор принимает Consolidator, Reindexer,
     Decayer, DedupSweeper и параметры: `interval time.Duration` (из `decay_interval`),
     `consolidateAfter time.Duration`.
   - `RunOnce(ctx)`: последовательно Decay (demoteAfter = consolidateAfter,
     archiveAfter = 4×consolidateAfter — задокументировать выбор) → Sweep →
     `Consolidate(consolidateAfter, 50)` → досчёт векторов через Reindexer. Ошибка
     одного джоба → лог в stderr, остальные выполняются (деградация §15). Результаты
     всех джобов — одной строкой лога.
   - `Run(ctx)`: `RunOnce` сразу при старте, затем по тикеру `interval`; выход по
     `ctx.Done()`. Паника внутри джоба не должна ронять процесс (recover + лог).
2. `internal/config`: распарсить `decay_interval`/`consolidate_after` в `time.Duration`
   (метод(ы) на MaintConfig с валидацией; невалидная строка → ошибка при загрузке конфига).
3. `cmd/memoryd/main.go`: собрать Scheduler из уже созданных зависимостей и запустить
   `go scheduler.Run(ctx)` тем же ctx, что MCP-сервер. Логи только в stderr (stdout — MCP!).
4. Тесты: `RunOnce` с фейками/in-memory store — все джобы вызваны, ошибка одного не
   мешает другим; парсинг MaintConfig (валид/невалид); тикер не тестировать (тривиален),
   достаточно RunOnce.

## Границы

Не менять логику самих джобов. Не трогать `mcp`, `recall`, `write`, `embed`, `store`.

## Критерий приёмки

- Билд чист; `CGO_ENABLED=1 go test -tags sqlite_fts5 -count=1 ./...` зелёный целиком.
- memoryd стартует, в stderr виден первый прогон джобов, stdout чист (MCP работает).
