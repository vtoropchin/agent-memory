# Задача 10.2 — Курирование памяти из web-морды: правка importance и tags

**Статус:** ✅ выполнена
**Этап:** 10 (Web v2) · **Область:** `cmd/memoryd` (web.go) + `cmd/memoryd/web` (фронтенд)
**Зависимости:** Этап 6 выполнен.

## Контекст

Морда показывает память и умеет мягко удалять, но малейшая правка («этому факту
завысили важность», «забыли тег») требует идти в сессию агента и звать
`memory_update` руками. Для курирования памяти человеком не хватает правки
**метаданных** прямо в карточке. Принципиальная граница остаётся: **content из
браузера не редактируется** — содержание фактов меняет агент через MCP (или
supersede новой записью); морда правит только сигналы ранжирования (importance)
и группировку (tags). Это второй write-эндпоинт морды после DELETE из 6.2 — та же
модель безопасности (localhost-only, доменный Writer, никакого сырого SQL).

## Что сделать

### Часть A — API (`web.go`)

`PATCH /api/memories/{id}`, тело:

```json
{ "importance": 5, "tags": ["стек", "решение"] }
```

- Оба поля опциональны; отсутствующее — не трогать (частичный PATCH). Пустой
  массив `tags: []` — валидное «снять все теги» (семантика Tags в write —
  заменяющая, в отличие от аддитивных Links — уже так).
- Реализация — строго через `write.Writer.Update` (`UpdateInput{Importance, Tags}`):
  кламп importance, updated_at, синхронизация FTS — всё уже в домене, ничего не
  дублировать. Content/kind/scope в PATCH **не принимаются** — присутствие лишнего
  поля в теле → 400 с перечнем допустимых (защита от расширения контракта втихую).
- Ответы: 200 + обновлённый memoryDTO; 404 — нет записи; 400 — битый JSON /
  importance вне 1..5 после клампа не бывает (кламп в write) — решить и
  задокументировать: либо 400 до вызова (строгий API), либо кламп (как MCP);
  рекомендация — кламп, симметрично MCP-поведению.
- Тумстоун (superseded) — 409 «запись архивирована, правка недоступна».

### Часть B — фронтенд (карточка записи)

- Importance: пять звёзд-кнопок (текущее значение подсвечено) → клик = PATCH.
- Tags: редактирование списка (добавить/удалить чип, ввод по Enter) → кнопка
  «Сохранить теги» = PATCH (не слать запрос на каждый чип).
- После успешного PATCH — обновить карточку из ответа; ошибка → ненавязчивая
  плашка с текстом, значения откатить к серверным.
- Стиль — существующие компоненты Tailwind морды (как кнопка удаления из 6.3:
  компактно, безопасное экранирование через `textContent`).

## Границы

- `internal/*` не трогать вовсе (Writer.Update уже умеет всё нужное). Только
  web.go + фронтенд + тесты.
- Никакой правки content/kind/scope/links из морды. Никакой массовой правки
  (bulk) — только одна запись за запрос.

## Тесты

`web_test.go` (httptest): PATCH importance → значение в БД изменилось, updated_at
сдвинулся, accessed_at НЕ сдвинулся (decay-часы не сбрасываются — тот же инвариант,
что в 4.1); PATCH tags заменяет полностью, `[]` снимает все, FTS-поиск по новому
тегу находит запись; частичный PATCH не трогает второе поле; лишнее поле в теле →
400; несуществующий id → 404; superseded → 409; битый JSON → 400.

## Критерий приёмки

- Билд/vet/тесты `-tags sqlite_fts5` зелёные.
- e2e на реальной БД: в браузере поменять важность и теги записи → перезагрузка
  страницы показывает новые значения; recall через MCP отражает новую importance
  в ранжировании.
- DESIGN §12: абзац про web-морду дополнен второй write-операцией (PATCH метаданных),
  с явной границей «content — только через MCP/агента».
