# Задача 8.4 — OpenAI-совместимый Embedder-бэкенд

**Статус:** ✅ выполнена
**Этап:** 8 (Качество recall) · **Область:** `internal/memory/embed` + `cmd/memo` (фабрика) + `internal/config`
**Зависимости:** нет.

## Контекст

DESIGN §6/§9/§13 с самого начала закладывают `provider = "openai"`
(`text-embedding-3-small`) как опцию за тем же интерфейсом `Embedder`, но реализованы
только `noop` и `ollama`. Пользователи без локальной ollama (или на машинах без GPU/
с медленным CPU-эмбеддингом) остаются на чистом FTS5. Endpoint `/v1/embeddings` —
де-факто стандарт: одна реализация покрывает OpenAI, OpenRouter, LM Studio, vLLM и
прочие совместимые серверы (поэтому `base_url` конфигурируем).

Образец для симметрии — `embed/ollama.go` (пробный эмбеддинг в конструкторе,
автоопределение dim, кэш sha256, `WithHTTPClient` для httptest) и `reason/deepseek.go`
(OpenAI-совместимый клиент, ключ из env).

## Что сделать

### Часть A — `internal/memory/embed/openai.go`

- Тип `OpenAI` (реализует `Embedder`), `NewOpenAI(ctx, baseURL, model, apiKey, opts...)`:
  - **пробный эмбеддинг в конструкторе** — проверка ключа/модели + определение `dim`
    из ответа (не хардкодить 1536; работает для любой совместимой модели);
  - `Embed`: POST `{base_url}/v1/embeddings`, тело `{"model", "input": [...]}`,
    заголовок `Authorization: Bearer <key>`; ответ `{"data":[{"embedding":[...],
    "index":N}]}` — **пересобрать по `index`** (порядок в ответе не гарантирован —
    отличие от ollama!); не-2xx / несовпадение количества → ошибка;
  - пустой `texts` → nil без запроса; опция `WithHTTPClient`;
  - кэш — тот же паттерн, что в ollama (`sha256(model+"\x00"+text)`, сброс при
    >10000). Известный тех-долг «truncate дублируется в embed/reason» разрастётся
    третьей копией — если понадобится truncate/кэш, **вынести общий приватный хелпер
    внутри пакета embed** (ollama переключить на него), межпакетную унификацию с
    reason не делать (вне границ).
- Только stdlib.

### Часть B — конфиг и фабрика

- `config`: в `EmbedderConfig` ничего нового не нужно (`provider/base_url/model` уже
  есть); ключ — **только из env `OPENAI_API_KEY`** (в TOML не пишется — правило §13
  как у DEEPSEEK_API_KEY; `.env`-загрузчик memo уже подхватит).
- `newEmbedder` в `cmd/memo/main.go`: ветка `"openai"` → пустой ключ → предупреждение
  + Noop (симметрично деградации ollama; ключ — рантайм-условие, не опечатка конфига);
  ошибка конструктора (сеть/невалидный ключ) → предупреждение + Noop. Дефолт base_url
  при пустом — `https://api.openai.com`.
- `config.example.toml`: закомментированный блок openai с пояснением про env-ключ.

### Важное про смену провайдера

Ничего дополнительно делать не нужно — подчеркнуть в отчёте: `embed_meta` хранит
model+dim, существующий Reindexer при несовпадении сам пересоздаст vec-таблицу и
перегонит все записи новой моделью (это уже проверенный путь смены модели).

## Тесты

`openai_test.go` (httptest, по образцу ollama_test.go): конструктор определяет dim;
Embed маппит по `index` (ответ с перепутанным порядком → правильный порядок векторов);
не-2xx → ошибка; пустой texts → без запроса; кэш срабатывает (счётчик запросов);
`main_test.go`: фабрика — пустой ключ → Noop, недоступный сервер → Noop,
валидный httptest → `*embed.OpenAI`.
