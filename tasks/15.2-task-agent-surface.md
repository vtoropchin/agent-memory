# Задача 15.2 — Поверхность агента: MCP, CLI и скиллы для новых полей задачи

**Статус:** ⬜ ожидает
**Этап:** 15 (Kanban-доска задач, DESIGN.md §14 Этап 15) · **Область:**
`internal/mcp` (`schema.go`, `save.go`, `update.go`, `recall.go`, `get.go`,
`instructions.go`), `cmd/memo` (`cli.go`, `skill.go`, `bootstrap_skill.go`),
`.claude/skills/memo/SKILL.md` (скилл этого репозитория)
**Зависимости:** 15.1 (поля `Type`/`Branch`/`Workflow`, стадии, `Query.Types`).
Независима от 15.3.

## Контекст

15.1 ввела в ядро стадии-колонки и поля `type`/`branch`/`workflow`, но агент
пока не может их ни задать, ни увидеть: MCP-схемы, CLI и инструкции знают
только `status`. Эта задача — доставка модели до агента: схемы инструментов,
инструкции сервера (главный канал конвенций — DESIGN.md §12), генерируемые
`memo init` скиллы, CLI-флаги.

Конвенции для агентов (фиксируются в `instructions.go` и скиллах, DESIGN.md
§14 Этап 15):

- стадии: `backlog` — сырая идея, `todo` — готова к работе, `doing` — в работе,
  `review` — ревью кода (PR открыт), `testing` — проверка/тестирование,
  `release` — влито, ждёт релиза, `done` — в релизе; переходы назад допустимы;
- `type`: `epic` — крупная цель, дробится на `story`; `story` — пользовательская
  история, дробится на `task`; `task` — атомарная единица работы (дефолт);
  иерархия — `links` с `rel=part_of` **от дочерней к родительской** (задача
  `part_of` истории, история `part_of` эпика) — теги `epic`/`эпик`/`История`
  больше не нужны;
- при переводе в `doing` агент проставляет `branch` (текущая git-ветка) и
  `workflow` (имя процесса: `dev`, `ultracode`, `code-review`, …);
- `memory_recall(types:["epic"])` — список эпиков; `statuses` без `blocked`.

## Что сделать

### A — MCP-схемы: `internal/mcp/schema.go`

- `saveInput`: `Type string` (`json:"type,omitempty"`, enum из
  `memory.TaskTypes`, описание: «тип задачи, только для kind=task: epic|story|
  task, пусто → task»), `Branch string`, `Workflow string` (описания по
  конвенциям выше). `updateInput`: те же три поля указателями (`*string`;
  пустая строка у branch/workflow — очистить). `recallInput`: `Types []string`
  (enum items из `memory.TaskTypes`). Enum `status`/`statuses` уже выводится из
  `memory.Statuses` — проверить, что `blocked` исчез, а 7 стадий на месте
  (обновить `schema_test.go`).
- `save.go`/`update.go`/`recall.go`: проброс в `write.SaveInput`/`UpdateInput`/
  `memory.Query` один в один. Ошибки `write.ErrUnknownTaskType`/
  `ErrTaskFieldNotApplicable` — читаемым текстом инструмента, как сейчас
  `ErrStatusNotApplicable`.
- `get.go` (`memory_get`): в блоке метаданных — `type`, `status`, `branch`,
  `workflow` (пустые не выводятся).

### B — инструкции сервера: `internal/mcp/instructions.go`

- Переписать пункты про `kind=task`: перечень стадий с расшифровкой, `type` и
  направление `part_of`, `branch`/`workflow` при взятии в работу, примеры
  `memory_recall(statuses:["todo","doing"])`, `memory_recall(types:["epic"])`.
  Убрать `blocked` из примеров. Тест `instructions_test.go` — обновить.

### C — CLI: `cmd/memo/cli.go`

- `memo save`: флаги `-type`, `-branch`, `-workflow` (только с `-kind task`;
  ошибка из write path — как есть). `-status` — описание с новыми стадиями.
- `memo recall`: `-types` (CSV), описание `-statuses` без `blocked`.
- Тесты `cli_test.go` на разбор флагов и проброс.

### D — генерируемые скиллы и скилл репозитория

- `cmd/memo/skill.go`, `cmd/memo/bootstrap_skill.go`: раздел «Задачи» —
  стадии, `type` + `part_of` дочь→родитель, `branch`/`workflow`, примеры
  запросов. Тесты на содержимое сгенерированного скилла (если есть) —
  обновить.
- `.claude/skills/memo/SKILL.md` этого репозитория — тот же раздел, чтобы
  догфуд-агенты сразу работали по конвенции. Перегенерировать скилл `memo`
  через `memo init` НЕ нужно — правится вручную и симметрично.

## Границы

- НЕ трогать ядро (`types.go`, `write`, `recall`, `store`) — если чего-то не
  хватает, это дефект 15.1: описать в отчёте, не чинить «заодно».
- Блокировки (`rel=blocked_by`, `unlinks`) — 15.4; секции родитель/дети в
  `memory_get` — 15.3.
- Новых MCP-инструментов не добавлять; `memo task` подкоманда — отложена (§14).

## Тесты

- `internal/mcp/task_test.go`: схемы принимают `type`/`branch`/`workflow`/
