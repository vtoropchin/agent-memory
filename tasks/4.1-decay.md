# Задача 4.1 — Decay (устаревание episodic)

**Статус:** ✅ выполнена (2026-07-11) — билд чист, `go test ./...` зелёный; арх-ревью + /code-review (high) + /simplify — без находок
**Этап:** 4 (Maintenance) · **Пакеты:** `internal/memory/maint`, `internal/memory/store`
**Зависимости:** нет (пакет maint уже существует)

## Контекст

DESIGN.md §11: понижаем вес неиспользуемых episodic, старьё архивируем. §4: сигналы —
`importance`, `accessed_at`, `access_count`; мягкое забывание — `superseded_by`
(в проекте это self-supersede-тумстоун, см. .claude/memory/mvp-notes.md). Semantic и
procedural decay НЕ подлежат (§2: живут долго).

## Что сделать

1. Расширить интерфейс `Store` методом
   `ListEpisodicForDecay(ctx context.Context, notAccessedSince int64, limit int) ([]Memory, error)`:
   episodic без `superseded_by`, у которых `COALESCE(accessed_at, created_at) < notAccessedSince`;
   сортировка по этой дате (старые первыми); `limit ≤ 0` — без лимита. Реализация в
   sqlite.go + тест. Комментарий со ссылкой на §11.
2. Новый файл `internal/memory/maint/decay.go`:
   - Тип `Decayer` (Store), конструктор `NewDecayer`.
   - `Decay(ctx, demoteAfter, archiveAfter time.Duration, limit int) (DecayResult, error)`:
     - Кандидаты: `ListEpisodicForDecay(now - demoteAfter, limit)`.
     - Запись «не трогали дольше archiveAfter» И `importance <= 1` → архив:
       `Supersede(id, id)` (тумстоун, как forget).
     - Иначе → понизить importance на 1 (минимум 1) прямым обновлением записи
       (`Put` с тем же id и updated_at=now, если Store так умеет — посмотри, как Update
       делает write.Writer, и переиспользуй Writer при необходимости — тогда зависимость
       Decayer'а — Store + *write.Writer).
     - Записи с `access_count > 0`, к которым обращались недавно, в кандидаты не попадают
       по условию SQL — отдельной логики не нужно.
   - `DecayResult{Scanned, Demoted, Archived int}`.
   - Дефолты порогов задаёт вызывающий (планировщик, 4.3); в этом пакете констант-порогов
     не хардкодить.
3. Тесты с in-memory store: старый неиспользуемый episodic понижается; понижение до 1 +
   возраст archiveAfter → тумстоун и выпадение из SearchLexical; semantic не трогается;
   недавно accessed (Touch) не трогается; повторный Decay идемпотентен по архиву.
