# Задача 5.3 — Подкоманда `memoryd init`: скаффолдинг настройки проекта

**Статус:** ✅ выполнена (2026-07-11) — подкоманда `memoryd init` (`cmd/memoryd/init.go`),
цель `make install`; арх-ревью 0 отклонений, code review (1 low → закрыт валидацией имени),
e2e через живой бинарь (генерация/идемпотентность/-force/старт сервера).
**Этап:** 5 (Догфудинг) · **Область:** `cmd/memoryd` (только)
**Зависимости:** 5.2 (формат `.mcp.json` + `agentmemory.toml` уже определён)

## Контекст

После 5.2 подключение memoryd к новому проекту — это ручное копирование двух файлов
(`.mcp.json` + `agentmemory.toml`) с правкой одной строки `[scope] project`. Нужно
автоматизировать: одна команда раскладывает оба файла с правильным именем проекта.

Решения пользователя по дизайну:
- **Самодостаточный проект:** генерируем ОБА файла в каталог проекта (никакого
  глобального конфига, загрузку конфига НЕ трогаем). `agentmemory.toml` коммитится
  вместе с репозиторием — воспроизводимо и переносимо.
- **Форма — подкоманда `memoryd init`** (не отдельный бинарь): один бинарь и для
  сервера, и для скаффолдинга (паттерн `git init`).

## Что сделать

Только пакет `cmd/memoryd`. Новые файлы `init.go` + `init_test.go`; правка `main.go`
(диспетчеризация подкоманды). Доменные пакеты (`config`, `mcp`, `store`, ...) и
поведение серверного пути — НЕ трогать.

### 1. Диспетчеризация в `main.go`
До разбора серверных флагов: если `len(os.Args) >= 2 && os.Args[1] == "init"` →
выполнить init-режим (разобрать `os.Args[2:]` через отдельный `flag.NewFlagSet("init",
flag.ExitOnError)`) и завершиться. Иначе — текущий серверный поток без изменений
(`memoryd`, `memoryd -config ...`, `memoryd -db ...` работают как раньше).

### 2. Подкоманда `init` (`init.go`)
Флаги:
- `-project string` — имя проекта (→ `[scope] project`). Дефолт: базовое имя каталога
  `-dir`. Если после дефолта имя пустое/`.`/`/` — ошибка с просьбой указать `-project`.
- `-dir string` — целевой каталог. Дефолт `.` (текущий).
- `-force` — перезаписывать существующие файлы. По умолчанию false: существующий файл
  ПРОПУСКАЕТСЯ с предупреждением (не ошибка) — повторный запуск идемпотентен и безопасен.

Генерирует в каталоге `-dir`:
- **`.mcp.json`** — сервер `agentmemory` (stdio):
  - `command` — абсолютный путь текущего бинаря через `os.Executable()` (после
    `go install` — стабильный путь установленного memoryd); при ошибке `os.Executable()`
    — фолбэк на строку `"memoryd"` (расчёт на PATH).
  - `args` — `["-config", "${CLAUDE_PROJECT_DIR:-.}/agentmemory.toml"]`.
  - `env` — `{"DEEPSEEK_API_KEY": "${DEEPSEEK_API_KEY:-}"}`.
  - Валидный JSON, отступ 2 пробела.
- **`agentmemory.toml`** — полный конфиг по образцу корневого `agentmemory.toml`/
  `config.example.toml`: `[store] path="~/.agentmemory/memory.db"`, `[embedder]`
  ollama/bge-m3, `[reasoner]` deepseek/deepseek-chat, `[recall]` (бюджет+веса), `[maint]`
  24h/168h, `[scope] project="<имя>" shared=["user:*"]`. Шаблон — константа-строка в
  коде с подстановкой имени проекта (не через toml.Marshal — чтобы сохранить комментарии).
  Имя проекта подставлять безопасно (обычная строка; если хочется — экранировать кавычки).

Вывод (stdout — это CLI-режим, не MCP): какие файлы записаны/пропущены, имя проекта,
путь БД, и следующий шаг («перезапусти Claude Code в этом каталоге и одобри сервер
`agentmemory`; убедись, что memoryd доступен — `go install` кладёт его на PATH»).

### 3. Makefile
Добавить цель `install`: `CGO_ENABLED=1 go install -tags sqlite_fts5 ./cmd/memoryd`.

## Границы

Только `cmd/memoryd` (+ строка в Makefile). Не менять `internal/*`, не менять серверное
поведение, не трогать загрузку/формат конфига. Никаких новых зависимостей (только stdlib:
`os`, `flag`, `path/filepath`, `encoding/json`, `fmt`, `text/template` или ручная сборка).

## Тесты (`init_test.go`)

- init в temp-каталог пишет оба файла; `.mcp.json` — валидный JSON с сервером
  `agentmemory`; `agentmemory.toml` через `config.Load` даёт `Scope.Project == <имя>`,
  embedder=ollama, reasoner=deepseek (round-trip проверка сгенерированного конфига).
- дефолтное имя проекта = базовое имя каталога; `-project` переопределяет.
- существующий файл без `-force` пропускается (содержимое не изменилось); с `-force`
  перезаписывается.
- пустое/невалидное имя проекта → ошибка.

## Критерий приёмки

- `CGO_ENABLED=1 go build/vet/test -tags sqlite_fts5 -count=1 ./...` — зелёное.
- `memoryd init` в свежем каталоге создаёт рабочие `.mcp.json` + `agentmemory.toml`
  с корректным `project`; серверный запуск (`memoryd`, `-config`, `-db`) не сломан.
