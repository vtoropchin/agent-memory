# Задача 4.2 — Dedup-sweep (чистка почти-дублей)

**Статус:** ⏳ ожидает
**Этап:** 4 (Maintenance) · **Пакеты:** `internal/memory/maint`, возможно `internal/memory/write`
**Зависимости:** нет

## Контекст

DESIGN.md §11: dedup sweep — чистка накопившихся почти-дублей (SimHash). Write path уже
дедуплицирует при записи (`internal/memory/write/simhash.go`, `isNearDuplicate`), но дубли
накапливаются в обход (импорт, консолидация, правки content). Sweep — ретроактивная чистка.

## Что сделать

1. SimHash-функции сейчас непубличны в пакете `write`. Экспортировать минимум, нужный
   maint (например `write.SimHash(text) uint64` и `write.IsNearDuplicate(a, b uint64) bool`
   или порог-константу), НЕ дублируя реализацию в maint. Существующее поведение write
   не менять.
2. Новый файл `internal/memory/maint/dedup.go`:
   - Тип `DedupSweeper` (Store), конструктор `NewDedupSweeper`.
   - `Sweep(ctx) (DedupResult, error)`:
     a. `AllForReindex(ctx)` (все живые записи), сгруппировать по `scope` — дедуп только
        внутри scope (как в write path).
     b. Внутри scope: SimHash по content, найти пары ближе порога. Из пары выживает
        запись с большим `importance`, при равенстве — более новая (`created_at`).
        Проигравшая → `Supersede(loserID, winnerID)`.
     c. Уже обработанные (superseded в этом же проходе) повторно не сравнивать.
   - `DedupResult{Scanned, Superseded int}`.
   - O(n²) внутри scope допустимо (объёмы малые), отметить комментарием.
3. Тесты: два почти-дубля в одном scope → один supersede в пользу более важного/нового;
   одинаковый текст в разных scope НЕ дедупится; цепочка из трёх похожих → выживает одна;
   непохожие не трогаются; повторный Sweep идемпотентен (0 новых supersede).

В `write` — только экспорт хелперов (переименование), без изменения логики.
