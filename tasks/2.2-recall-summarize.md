# Задача 2.2 — Суммаризация recall-выдачи через Reasoner

**Статус:** ✅ выполнена (2026-07-11). Билд чист, все тесты зелёные.
**Этап:** 2 (Reasoner) · **Пакеты:** `internal/memory/recall`, `internal/mcp`, `internal/memory` (types)
**Зависимости:** нет (работает через интерфейс `reason.Reasoner`)

## Контекст

`internal/memory/recall/recall.go` — Recaller собирает Markdown-бриф
(FTS → RRF → ранжирование → сборка под token_budget). DESIGN.md §8: опционально Reasoner
сжимает найденное в абзац. §12: инструмент `memory_recall`. §15: деградация, а не падение.

## Что сделать

1. `internal/memory/types.go`: поле `Query.Summarize bool` — запросить LLM-сводку брифа.
2. `internal/memory/recall/recall.go`: Recaller получает зависимость `reason.Reasoner`
   (расширить конструктор `New`; поправить все места вызова, включая тесты и
   `cmd/memoryd` — там временно `reason.NewNoop()`). При `q.Summarize`:
   после сборки брифа вызвать `Complete` с промптом «Сожми выжимку памяти в один короткий
   абзац-сводку (3–5 предложений), сохрани язык исходных записей, не выдумывай фактов» +
   текст брифа. Непустой результат — секция `### Сводка` в начале Markdown.
   Пустая строка ИЛИ ошибка → бриф без сводки, ошибку наружу не отдавать
   (лог в stderr). Сводка не участвует в token_budget-обрезании записей.
3. `internal/mcp`: опциональное boolean-поле `summarize` в схеме `memory_recall`
   (единообразно с остальными полями), проброс в `memory.Query`.
4. Тесты: фейковый Reasoner — успех (сводка в начале), ошибка (бриф без сводки и без
   ошибки), `Summarize=false` (Complete не вызывается), Noop (бриф не меняется).
