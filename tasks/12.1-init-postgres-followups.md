# Задача 12.1 — `memo init` + postgres: проверка готовности базы и подсказка про `memo migrate`

**Статус:** ⬜ ожидает
**Этап:** 12 (Общая память команды, DESIGN.md §14 Этап 12) · **Область:** `cmd/memo` (`init.go`, `wizard.go`)
**Зависимости:** выбор бэкенда хранилища в `memo init` (уже сделан: `-store-driver`,
`-postgres-*`, read-only проба подключения).

## Контекст

`memo init` теперь умеет настроить PostgreSQL-хранилище сам и перед записью файлов делает
**read-only** пробу подключения (`store.OpenPostgresReadOnlyContext` + `Health` — соединение,
`current_schema()`, `SELECT 1`/`SHOW server_version`/`pg_is_in_recovery`; накатывать
прод-схему памяти в общую командную базу «за компанию» с проверкой доступности он права не
имеет, DESIGN.md §15 и комментарий у `probeStoreConnectionLive`).

Отсюда три осознанно оставленных пробела:

1. **Проба проверяет доступность, но не готовность.** «Сервер отвечает и база открывается»
   не означает, что первый штатный старт `memo` пройдёт: у роли может не быть прав на
   `CREATE` в целевой схеме, а расширение `pgvector` может быть не установлено (тогда
   векторный слой молча не поднимется при первом `ResetVectorIndex`). Сейчас это выяснится
   не в `memo init`, а позже — при старте сервера или при reindex.
2. **Про перенос накопленной памяти init молчит.** Разработчик, у которого уже есть
   локальный SQLite с памятью, после `memo init -store-driver postgres` получает пустую
   общую базу и нигде в выводе не видит, что для переезда есть `memo migrate` (README,
   раздел «Общая база команды», шаг 3).
3. **`MEMO_POSTGRES_PASSWORD` не пробрасывается в MCP-конфиг.** Для ключей провайдеров
   `memo init` кладёт в `.mcp.json`/`opencode.json` плейсхолдеры (`${DEEPSEEK_API_KEY:-}`,
   `{env:OPENAI_API_KEY}` — см. `buildProviderEnv`), для пароля БД — нет. Сегодня это
   работает: memo сам подхватывает пароль из `.env` рядом с конфигом при старте
   (`loadDotEnv`). Добавлять плейсхолдер наугад не стали — сначала нужно проверить на
   живых харнессах, как Claude Code и opencode ведут себя с переменной, которой нет в
   окружении (пустой инжект против отсутствия ключа), и не перекроет ли пустое значение
   восстановление пароля из `.env` (в `loadDotEnv` пустое значение как раз перекрывается
   .env, но у opencode синтаксис интерполяции другой). Это отдельная задача с ручной
   проверкой обоих приложений, а не строчка в `buildProviderEnv`.

## Что сделать

- Расширить пробу read-only диагностикой готовности (всё — только `SELECT`, без DDL):
  наличие расширения `vector` (`pg_extension`) и права роли на создание объектов в текущей
  схеме (`has_schema_privilege(current_schema(), 'CREATE')`). Отсутствие — **предупреждение**
  в вывод с объяснением последствий, а не отказ (деградация, а не падение): база может
  готовиться администратором отдельно.
- Если целевое хранилище — postgres, а рядом (в `-dir` или по дефолтному
  `~/.agentmemory/memory.db`) есть непустой SQLite-файл, — напечатать в конце `memo init`
  готовую строку `memo migrate ...` для переноса. Только подсказка: сам перенос `init`
  делать не должен (это отдельная явная операция над чужими данными).
- Проверить на живых Claude Code и opencode поведение с плейсхолдером
  `MEMO_POSTGRES_PASSWORD` в MCP-конфиге (пункт 3) и, если оба харнесса ведут себя
  корректно, добавить его в `buildProviderEnv`/`buildOpencodeServerEntry`; если нет —
  зафиксировать в DESIGN.md §13, что пароль БД доезжает только через `.env`.
- Тесты — в стиле уже имеющихся: диагностика на подменяемой точке (`probeStoreConnection`),
  живая проверка — под `MEMO_TEST_POSTGRES_DSN` со `t.Skip` без него; общая база команды не
  чистится TRUNCATE/DROP, только read-only запросы.

## Границы

Не менять контракт `store.OpenPostgresReadOnly`/`OpenPostgresReadOnlyContext` (никакого DDL
из `init`/`doctor`), не менять сигнатуру `doInit(cfg, out)`, не трогать генерацию секций
TOML для остальных бэкендов.

## Критерий приёмки

`memo init -no-input -store-driver postgres ...` на базе без `pgvector`/без прав на CREATE
завершается успешно, но печатает внятное предупреждение о том, что именно не готово; при
наличии локального SQLite-файла в выводе есть готовая команда `memo migrate`; по пункту 3
принято и зафиксировано решение. `make build`, `make test` зелёные, в том числе с
`MEMO_TEST_POSTGRES_DSN`.
