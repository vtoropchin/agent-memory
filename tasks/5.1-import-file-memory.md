# Задача 5.1 — Импортёр файловой памяти (.claude/memory → memoryd)

**Статус:** ⏳ ожидает
**Этап:** 5 (Догфудинг) · **Пакет:** `cmd/memimport` (новый)
**Зависимости:** Этап 2 собран (write path стабилен); Этап 3 желателен, но не обязателен
(векторы досчитает reindex/backfill)

## Контекст

DESIGN.md §14 Этап 5: переезд разработки проекта с файловой памяти (`.claude/memory/`)
на собственный memoryd. Формат файлов — см. `.claude/memory/README.md` и сами файлы:
frontmatter (`name`, `kind`, `importance`, `tags`), тело — Markdown с `[[wiki-ссылками]]`
на `name` других записей.

## Что сделать

1. Новый бинарь `cmd/memimport/main.go` (CLI, не MCP):
   - Флаги: `-dir` (дефолт `.claude/memory`), `-db` (дефолт как у memoryd из конфига),
     `-scope` (дефолт `project:agentmemory`), `-dry-run` (печать без записи).
   - Пропускать `MEMORY.md` и `README.md`; остальные `*.md` — по одному факту на файл.
   - Парсинг frontmatter (простой ручной парсер: `key: value`, `tags: [a, b]` — без новых
     зависимостей): `name` → тег `name:<slug>` + Source `file-import:<slug>`; `kind` файла
     (`project`/`user`/`feedback`/`reference`) НЕ равен домену — мапить: всё → `semantic`,
     кроме файлов, где тело содержит явный рецепт-процедуру (маркер «Как применять» /
     «How to apply») → тоже `semantic` (процедуры у нас в файлах нет; procedural оставить
     на будущее). `importance` из frontmatter (clamp 1..5, дефолт 3), `tags` из frontmatter.
   - Тело файла (без frontmatter) → `content` как есть (Markdown допустим).
   - Два прохода: (1) сохранить все записи через `write.Writer.Save` (дедуп сработает
     штатно), запомнить slug→id; (2) `[[slug]]`-ссылки → `links` через `write.Writer.Update`
     (rel=related); ссылка на несуществующий slug → предупреждение в stdout, пропустить.
   - Итог в stdout: imported N, updated-with-links M, skipped-as-duplicate K, warnings.
2. Тесты `main_test.go` (или вынести парсер/импорт в функции и тестировать их):
   парсинг frontmatter (с tags-списком и без), пропуск README/MEMORY, двухпроходное
   связывание, dry-run ничего не пишет, дубль при повторном прогоне не плодится (дедуп).
3. В Makefile — цель `import` (`go run -tags sqlite_fts5 ./cmd/memimport`).

## Границы

Не трогать: `mcp`, `recall`, доменные пакеты (использовать существующие store/write).
Файлы в `.claude/memory/` НЕ удалять и не менять — источник остаётся до задачи 5.2.

## Критерий приёмки

- Билд чист; тесты зелёные. Живой прогон: `make import -- -dry-run` показывает все записи
  из `.claude/memory/`, реальный прогон кладёт их в БД, повторный прогон не создаёт дублей;
  `memory_recall` через memoryd находит импортированное (проверка оркестратором).
