## Контекст

Рантайм умеет embedder `ollama | openai | noop` (8.4) и reasoner `deepseek | noop`, но
`memoryd init` жёстко пишет `provider = "ollama"` / `provider = "deepseek"`, спрашивает
только ollama URL/модель и ключ DeepSeek. Провайдер эмбеддинга не выбирается, `OPENAI_API_KEY`
`init` не умеет ни спросить, ни записать в `.env`, ни пробросить в `.mcp.json`. Плюс
интерактив сейчас — ввод строк и **цифр пунктов** через `bufio.Scanner` (`promptChoice`),
что неудобно.

Пробелы (аудит): (1) провайдер эмбеддинга не выбирается; (2) `.mcp.json` пробрасывает только
`DEEPSEEK_API_KEY` ([init.go:484]); (3) `.env` знает только про ключ DeepSeek; (4) reasoner
жёстко `deepseek` (нет выбора `noop`). Пункты 1–3 — единый недоделанный сценарий openai.

Пользователь хочет: перейти на **cobra**, при выборе openai — **взять токен и запросить у
OpenAI доступные модели эмбеддинга**, для ollama — **запросить реально установленные модели**,
чтобы не вводить руками; интерактив — **выбор с клавиатуры (стрелками), не ввод цифр**; ключи
спрашивать **только у выбранных провайдеров**.

> Осознанный трейдофф к DESIGN §1 («ноль тяжёлых зависимостей на старте»): cobra и TUI-
> библиотека — это зависимости **инсталлятора/CLI**, а не ядра памяти (Store/recall/write).
> Ядро остаётся без новых зависимостей. Зафиксировать это в отчёте, чтобы ревью не считало
> нарушением принципа.

## Что сделать

### Спайк (короткий, результат — раздел «Решение» в этом файле)

Выбрать TUI-библиотеку для интерактива стрелками. Требования: одиночный select с навигацией
стрелками/Enter; текстовый ввод; **скрытый ввод (password) для API-ключей**; корректная
работа и **graceful-фолбэк при не-TTY** (пайп/`-no-input` → без TUI). Кандидаты:
`github.com/charmbracelet/huh` (рекомендуемый — современный, формы/группы, password-поле,

обосновать в «Решении». cobra — `github.com/spf13/cobra` (без вариантов).

### Часть A — миграция CLI на cobra

Переписать разбор аргументов `cmd/memoryd` на cobra, **сохранив поведение байт-в-байт**.
Бизнес-логику подкоманд (`runRecall`/`runSave`/`runHook`/`runDoctor`/`runExport`/`runImport`/
`runInit`/`runWeb`/`run` — сервер) НЕ переписывать: cobra меняет только обёртку разбора флагов.

- **Корневая команда `memoryd`**: при вызове **без подкоманды** — MCP-сервер (stdio), как
  сейчас `run()`. Это критично для обратной совместимости: установленный `.mcp.json` зовёт
  `memoryd -config <toml>` **без подкоманды** — должен по-прежнему подниматься сервер.
  `-config` — persistent-флаг корня, наследуется подкомандами.
- Подкоманды: `init`, `web`, `recall`, `save`, `hook`, `doctor`, `export`, `import`.
- **Сохранить контракты exit-кодов и потоков** (регрессионный чек-лист приёмки):
  - `hook`: **любая ошибка → пустой stdout, exit 0** (хук не ломает сессию). Осторожно с
    cobra: по умолчанию она печатает ошибку/usage и ставит ненулевой код — для `hook`
    RunE НЕ должен возвращать ошибку (обрабатывать внутри), `SilenceUsage`/`SilenceErrors`.
  - `recall`/`save`: 0 успех (в т.ч. пустой recall), 1 — ошибка; stdout только бриф/`saved <id>`,
    логи только stderr. `SilenceUsage`/`SilenceErrors`, чтобы cobra не засоряла stdout.
  - `doctor`: exit 0 (здоров/деградирован) / 1 (есть ❌) — код из отчёта, а не «ошибка cobra».
  - `init`/`export`/`import`: 0/1 как сейчас; `-dry-run` у import — БД не открывается на запись.
- Справка `--help` — на русском (портировать существующие тексты usage), в стиле memoryd.
- `.env`-загрузка (`loadDotEnvForConfig`) и семантика `-config` сохранены для всех подкоманд.

### Часть B — переработка `init`: провайдеры, динамические модели, интерактив

Интерактивный сетап (TTY) — форма с выбором стрелками. Порядок и ветвление:

1. **Агент** (claude/opencode) — select.
2. **Имя проекта** — ввод (дефолт — имя каталога).
3. **Провайдер эмбеддинга** — select `ollama` (дефолт) / `openai` / `noop`.
   - **ollama** → запросить у ollama **реально установленные модели** (`GET {base_url}/api/tags`,
     поле `.models[].name`) и показать их **select-списком**; base_url спросить до этого
     (дефолт `http://localhost:11434`). Если ollama недоступен/список пуст → фолбэк на ручной
     ввод модели (дефолт `bge-m3`), не блокировать установку.
   - **openai** → сначала **запросить токен** (скрытый ввод), затем **запросить доступные
     модели эмбеддинга** (`GET {base_url}/v1/models` с `Authorization: Bearer <key>`,
     отфильтровать `.data[].id`, содержащие `embedding`) и показать **select-списком**;
     base_url спросить с дефолтом `https://api.openai.com` (для OpenRouter/LM Studio/vLLM).
     Если запрос упал (неверный ключ/сеть) или фильтр пуст → показать причину и фолбэк на
     ручной ввод модели (токен уже введён, повторно не спрашивать; при пустом фильтре можно
     показать все `.data[].id`).
   - **noop** → без вектора, модель/URL не спрашивать.
4. **Провайдер reasoner** — select `deepseek` (дефолт) / `noop`.
   - **deepseek** → запросить ключ DeepSeek (скрытый ввод; можно пропустить и указать позже).
   - **noop** → ключ не спрашивать.
5. **Путь к файлу БД** — ввод (дефолт `~/.agentmemory/memory.db`).
6. **Хуки** (ambient) — select, как сейчас (7.2).

**Ключи — только у выбранных провайдеров.** `.env` содержит только выбранные ключи; в
`.mcp.json` в `env` пробрасываются плейсхолдеры только выбранных провайдеров
(`OPENAI_API_KEY` — если embedder=openai; `DEEPSEEK_API_KEY` — если reasoner=deepseek). Ключи
в TOML не пишутся (§13). `.env` — права `0600`, строка `.env` в `.gitignore` (как сейчас).

**Шаблон `agentmemory.toml`** рендерит `[embedder]`/`[reasoner]` под выбранные провайдеры
(ollama: base_url+model; openai: base_url+model, коммент про env-ключ; noop: только provider;
deepseek: model; reasoner noop: только provider). `[recall]`/`[maint]`/`[scope]` — как сейчас.

**Не-интерактивный режим (`-no-input`)** — полностью на флагах/дефолтах, **без сетевых
запросов** (детерминизм, тестируемость): `-embedder-provider`, `-embedder-model`,
`-embedder-url`, `-reasoner-provider`, `-openai-key` (или из env `OPENAI_API_KEY`),
существующие `-deepseek-key`/`-ollama-url`/`-ollama-model` сохранить (можно как алиасы новых).
Динамическое получение моделей — **только в интерактивном TTY-режиме**.

**Функции получения моделей** вынести в тестируемые хелперы (напр. `fetchOllamaModels(ctx,
baseURL) ([]string, error)` и `fetchOpenAIEmbeddingModels(ctx, baseURL, key) ([]string, error)`)
на stdlib `net/http` — TUI поверх них тонкая обёртка. Вопрос, класть ли их в `cmd/memoryd`
(init-специфика) или добавить метод в `internal/memory/embed` — решить по месту; рекомендация:
в `cmd/memoryd`, чтобы не расширять доменный интерфейс ради инсталлятора.

## Тесты

- **Регрессия cobra** (обязательна): для каждой подкоманды сохранены exit-код и разделение
  stdout/stderr — особенно `hook` (ошибка → пустой stdout, exit 0), `recall`/`save` (stdout
  чист от usage/логов), `doctor` (0/1 по отчёту). Бэра-вызов `memoryd -config X` без
  подкоманды поднимает сервер (как `.mcp.json`).
- **`init` -no-input, все комбинации провайдеров**: ollama/openai/noop × deepseek/noop →
  корректные `agentmemory.toml` (нужные `[embedder]`/`[reasoner]`-блоки), `.env` (только
  выбранные ключи), `.mcp.json` `env` (только выбранные плейсхолдеры). Идемпотентность/merge
  settings.json и хуков сохранены (7.2).
- **Динамические модели** (httptest): `fetchOllamaModels` — успех/пустой/ошибка/парсинг
  `.models[].name`; `fetchOpenAIEmbeddingModels` — фильтр по `embedding`, неверный ключ →
  ошибка, пустой фильтр → фолбэк на все id. Живых обращений к OpenAI/ollama в тестах нет.
- TUI-виджет как таковой не юнит-тестируем (библиотека) — тестируется плумбинг данных под ним
  и `-no-input`-путь; TUI держать тонкой обёрткой над протестированными функциями.
