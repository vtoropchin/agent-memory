# Задача 5.2 — Подключение memoryd как MCP-сервера проекта (догфудинг)

**Статус:** ⏳ ожидает 5.1, MP-2
**Этап:** 5 (Догфудинг) · **Область:** инфраструктура репо (`.mcp.json`, Makefile, скилл `/dev`)
**Зависимости:** 5.1 (память импортирована), MP-2 (идентичность проекта + дефолты scope)

## Контекст

DESIGN.md §14 Этап 5: разработка проекта переезжает с файловой памяти на memoryd.
Скилл оркестратора — `.claude/skills/dev/SKILL.md` (раздел «Память проекта» прямо
предусматривает этот переезд). Часть шагов — конфигурация, а не Go-код.

## Что сделать

1. Сборка бинаря: цель Makefile `bin/memoryd` (`go build -tags sqlite_fts5 -o bin/memoryd
   ./cmd/memoryd`); `bin/` — в `.gitignore`.
2. `.mcp.json` в корне репо: сервер `agentmemory` — команда `bin/memoryd` со stdio,
   env/аргументы для конфига с локальной БД проекта (`.agentmemory/memory.db`;
   каталог — в `.gitignore`). Если memoryd не принимает путь конфига флагом — добавить
   флаг `-config` в `cmd/memoryd` (маленькая правка, разрешена).
3. Конфиг догфудинга `agentmemory.toml` в корне: `provider="deepseek"` (ключ из env),
   `provider="ollama"`/`bge-m3` для embedder, `[scope] project = "agentmemory"`
   (идентичность инстанса — MP-1/MP-2), путь БД. **Путь БД — общий** `~/.agentmemory/memory.db`
   (модель «один файл на все проекты», DESIGN.md §2.1), НЕ repo-local: так работает общий
   слой `user:*` между проектами.
4. Обновить `.claude/skills/dev/SKILL.md`, раздел «Память проекта»: вместо файлов —
   `memory_recall` в начале задачи (scope не указывать — инстанс сам подставит
   `project:agentmemory` + `user:*`) и `memory_save` в конце (проектные факты — без scope →
   в `project:agentmemory`; общие привычки/предпочтения — явно `scope: "user:*"`);
   файловую память объявить архивом (только чтение, новые факты — в memoryd).
5. Пометить `.claude/memory/README.md`: «архив, мигрировано в memoryd задачей 5.2,
   новые записи сюда не добавлять».
6. Проверка end-to-end (оркестратор): перезапуск MCP-серверов, `memory_recall` возвращает
   импортированные решения, `memory_save` кладёт новый факт, повторный recall его находит.

## Границы

Доменные пакеты не трогать (кроме опционального флага `-config` в cmd/memoryd).
Файлы `.claude/memory/*.md` не удалять — они остаются архивом/бэкапом.

## Критерий приёмки

- В новой сессии Claude Code доступны инструменты `memory_save/recall/update/forget`
  от сервера `agentmemory`, recall отдаёт мигрированные знания проекта.
