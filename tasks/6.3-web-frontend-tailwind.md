# Задача 6.3 — Frontend web-морды (Tailwind CDN)

**Статус:** ⏳ ожидает
**Этап:** 6 (Web-морда) · **Область:** `cmd/memoryd/web/` (статические `index.html` + `app.js`; без Go-кода)
**Зависимости:** 6.2 (embed-плумбинг + зафиксированный контракт JSON API)

## Контекст

Финальный слой web-морды: собственно интерфейс просмотра памяти в браузере. Бэкенд (6.2)
отдаёт JSON API и раздаёт эту статику из `embed.FS`. Здесь — только HTML/CSS/JS, без Go.

**Стек (решение пользователя):** **Tailwind CSS через CDN** —
`<script src="https://cdn.tailwindcss.com"></script>` прямо в `index.html`, zero-build (никакого
npm/Node/сборки). JS — ванильный (fetch + DOM), без фреймворков. Всё self-contained, встраивается
в бинарь через уже готовый `//go:embed web` из 6.2.

> Замечание про CDN: Tailwind Play CDN тянется из сети при открытии страницы — для локального
> dev-инструмента это норма. Офлайн-режим (бандл через standalone Tailwind CLI в
> `web/tailwind.css`) — возможное расширение на будущее, в этой версии не делаем.

## Контракт API (из 6.2 — потреблять как есть)

- `GET /api/stats` → `{total, superseded, byScope:{scope:count}, byKind:{kind:count}}`
- `GET /api/memories?scope=&kind=&superseded=1&limit=&offset=` (scope/kind повторяемы) →
  `{items:[memory...], total, limit, offset}`
- `GET /api/memories/{id}` → `{memory, neighbors:[memory...]}`
- `GET /api/search?q=&scope=&kind=&limit=` → `{items:[{...memory, score, source}]}`
- `memory`: `{id, kind, scope, content, summary, importance, createdAt, updatedAt,
  accessedAt, accessCount, supersededBy, source, tags:[], links:[{dst,rel}]}`
  (timestamps — unix-секунды; nullable-поля приходят как `null`).

## Что сделать

Заменить плейсхолдер из 6.2 на рабочий SPA в `cmd/memoryd/web/`:
- **`index.html`** — каркас + Tailwind CDN. Опрятная, отзывчивая раскладка, тёмная/светлая тема
  необязательна (если делать — через `dark:` классы и `prefers-color-scheme`).
- **`app.js`** — вся логика на fetch к API.

Интерфейс (UI-подписи на русском — проект русскоязычный):

1. **Шапка / дашборд** — из `/api/stats`: всего живых записей, архивных; бейджи-разбивки по kind
   (semantic/episodic/procedural) и по scope с числами. Клик по бейджу scope/kind — быстрый
   фильтр списка.
2. **Панель фильтров** (сайдбар или строка над списком):
   - строка поиска (Enter или debounce) → режим `/api/search`; пустая строка → режим browse
     `/api/memories`;
   - чекбоксы scope (из `stats.byScope`) и kind — множественный выбор (повторяемые query-параметры);
   - тумблер «показывать архивные» (`superseded=1`);
   - сброс фильтров.
3. **Список записей** — карточки: бейдж kind (цветовое кодирование по типу), scope, важность
   (★×importance), первые строки content, чипы tags, дата создания (из createdAt), пометка
   «архив», если `supersededBy != null`. В режиме поиска — доп. показ score. Пагинация
   (Назад/Вперёд по limit/offset, «показано X из total»).
4. **Карточка записи** (модалка или отдельная панель по клику) — из `/api/memories/{id}`:
   полный content, summary (если есть), kind/scope/важность, tags, timestamps
   (created/updated/accessed — человекочитаемо из unix-секунд), access_count, source,
   supersededBy. **Граф связей:** links (`{dst,rel}`) и neighbors — списком, каждый сосед
   кликабелен и открывает его карточку (навигация по графу памяти).

Требования к качеству:
- Обрабатывать пустые состояния (нет записей / пустой поиск) и ошибки API (показать
  `{"error":...}` понятным сообщением, не «молча пусто»).
- Экранировать пользовательский текст при вставке в DOM (content/tags/scope могут содержать
  спецсимволы) — через `textContent`, не сырой `innerHTML`.
- Аккуратно, читабельно, адаптивно (десктоп + узкий экран). Без тяжёлой графики.

## Границы

Только `cmd/memoryd/web/` (index.html + app.js, при желании мелкие вспом. ассеты). Go-код и API
не менять — если для UI не хватает данных/эндпоинта, зафиксировать это в отчёте как замечание к
6.2, а не расширять контракт самовольно. Единственная внешняя зависимость — Tailwind CDN; больше
никаких CDN/скриптов. Данные не мутировать (GET-only, кнопок правки/удаления нет).

## Проверка (verify — визуальная, флоу end-to-end)

Тестов Go здесь нет (только статика). Проверка — прогон живого `memoryd web` поверх реальной БД
(после импорта памяти проекта) и наблюдение в браузере:
- дашборд показывает ненулевую статистику; фильтры scope/kind/архив меняют список;
- поиск по знакомому слову находит запись;
- открытие карточки показывает tags/links; клик по соседу переходит на его карточку;
- пустой поиск и ошибочный сценарий не роняют страницу.

## Критерий приёмки

- `CGO_ENABLED=1 go build -tags sqlite_fts5 ./...` — зелёное (статика встраивается в бинарь).
- `memoryd web -db <файл>` + открытие `http://127.0.0.1:7070` даёт рабочую морду: список с
  фильтрами и поиском, карточка записи с навигацией по связям, дашборд статистики — на реальной
  памяти проекта. Верстка на Tailwind, опрятно и отзывчиво.
