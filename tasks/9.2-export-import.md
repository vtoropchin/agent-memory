# Задача 9.2 — `memoryd export` / `memoryd import`: бэкап и перенос памяти

**Статус:** ⬜ ожидает
**Этап:** 9 (Ops и модель данных) · **Область:** `cmd/memoryd` (подкоманды) + возможно 1–2 read/write-метода в `store`
**Зависимости:** нет.

## Контекст

Память — самый ценный артефакт системы, а живёт в одном файле SQLite без штатного
способа бэкапа/переноса: между машинами, при миграции схемы, при желании заглянуть
в память глазами/grep'ом. `cmd/memimport` умеет только импорт из `.claude/memory/*.md`
(легаси-формат). Нужен полный цикл: экспорт инстанса в переносимый JSON и импорт
обратно **с сохранением идентичности записей**.

## Формат экспорта

JSONL (одна запись — одна строка; стримится, диффается, grep'ается) + заголовочная
строка с метаданными:

```json
{"format":"agentmemory-export","version":1,"exported_at":1789300000,"db":"~/.agentmemory/memory.db"}
{"id":"01J...","kind":"semantic","scope":"project:agentmemory","content":"...","summary":"...","importance":4,"created_at":...,"updated_at":...,"accessed_at":...,"access_count":7,"superseded_by":null,"source":"...","tags":["a","b"],"links":[{"dst":"01K...","rel":"related"}]}
```

- **Векторы НЕ экспортируются** — производные данные; после импорта их досчитает
  существующий Reindexer (пустая embed_meta новой БД → полный reindex). Это резко
  упрощает формат и делает его независимым от модели эмбеддинга.
- Тумстоуны (superseded) экспортируются как есть — история переносится.

## Что сделать

### `memoryd export [-config path] [-o file.jsonl] [-scopes a,b]`

- `-o` пусто → stdout (пайпабельность). `-scopes` — частичный экспорт (напр. только
  один проект); пусто → вся БД.
- Обход: `store.List`/`AllForReindex` не подходят (первый — постранично без tags/links?
  второй — только живые). Проверить по факту; если полного обхода «все записи включая
  superseded, с tags и links» нет — добавить в store ОДИН метод
  `AllForExport(ctx) iter` (или постранично) — read-only.
- Детерминированный порядок (по id) — диффабельность экспортов.

### `memoryd import [-config path] file.jsonl [-dry-run] [-rescope old=new]`

- Проверка заголовка (format/version; неизвестная version → ошибка).
- **Сохранение id** (ULID) и всех таймстампов — импорт идёт через `store.Put` (или
  новый `store.PutRaw`, если Put что-то перетирает — проверить), НЕ через
  `write.Writer` (дедуп/классификация исказили бы восстановление бэкапа).
- Конфликт id (запись уже есть): по умолчанию skip + счётчик; флаг `-overwrite`
  заменяет. Links на отсутствующие id — warning + пропуск ребра (§15).
- `-rescope project:old=project:new` — перенос памяти между проектами при импорте.
- `-dry-run` — как в memimport: БД вообще не открывается на запись, только разбор
  и отчёт (архитектурная гарантия, не соглашение).
- Итоговая строка: `imported N, skipped M, links K (dropped L)`.
- После импорта напомнить в выводе: векторы досчитает первый запуск memoryd (reindex).

## Границы

- `cmd/memoryd` + минимальные store-методы (только перечисленные, зафиксировать в
  отчёте сигнатуры). `write`/`recall`/`maint`/`mcp`/web — не трогать.
- `cmd/memimport` не трогать (легаси-путь остаётся); в его README/справке можно
  упомянуть новый универсальный формат.

## Тесты

Round-trip как главный инвариант: export → import в пустую scratch-БД → повторный
export **байт-в-байт равен** первому (id, таймстампы, tags, links, тумстоуны
сохранены). Плюс: конфликт id (skip/overwrite); rescope переписывает scope и только
его; битая строка JSONL → ошибка с номером строки; dry-run не создаёт БД; частичный
экспорт по -scopes; links на отсутствующий id → warning, остальное импортируется.

## Критерий приёмки

- Билд/vet/тесты `-tags sqlite_fts5` зелёные.
- Живой прогон: экспорт реальной БД проекта → импорт в scratch → `memoryd recall`
  (или doctor из 9.1) над scratch-БД видит те же записи; после запуска memoryd
  векторы досчитаны (лог reindex).
