# Задача 12.3 — пустой `store.path` для sqlite молча открывает анонимную временную БД

**Статус:** ⬜ ожидает
**Этап:** 12 (Общая память команды, DESIGN.md §14 Этап 12) · **Область:**
`internal/config` (`config.go`), `internal/memory/store` (`sqlite.go`)
**Зависимости:** ревью задачи 12.2 (`tasks/12.2-sqlite-uri-escaping.md`) — найдено
попутно при разборе сборки sqlite-DSN.

## Контекст

`config.StoreConfig.Validate` (`internal/config/config.go`) для `driver="sqlite"`
(включая пустой `Driver` — дефолт) возвращает `nil` без единой проверки `Path`:

```go
switch c.Driver {
case "", "sqlite":
    return nil
```

Пустой `Path` доходит до `store.OpenSQLite("")` (`internal/memory/store/sqlite.go`).
`expandHome("")` не подходит ни под один из случаев (`path == "~"` /
`strings.HasPrefix(path, "~/")`) и возвращает `""` как есть; `sqliteDSN("", params)`
собирает DSN вида `"file:?_foreign_keys=on&_journal_mode=WAL&_busy_timeout=5000"`.
SQLite трактует `file:` без пути как **анонимную временную базу данных** (см.
https://www.sqlite.org/inmemorydb.html, раздел "Database Filename Is An Empty
String" — в отличие от `file::memory:`, это не in-memory, а именно приватный
временный файл на диске, который SQLite создаёт и удаляет сам). `OpenSQLite`
успешно накатывает схему поверх него и возвращает рабочий `*sqliteStore` — ни
ошибки, ни предупреждения.

Итог: если `store.path` в `agentmemory.toml` случайно оказался пустым (опечатка в
конфиге, шаблон/скрипт генерации конфига подставил пустую переменную,
`-store-path ""` явно) — `memo` не падает и не жалуется, а тихо работает поверх
одноразовой временной БД. Всё, что было сохранено за сессию, теряется без следа
при закрытии соединения — и ни `memo doctor`, ни обычный старт этого не заметят
(файла на диске, который можно было бы проверить `os.Stat`, для этого случая
попросту не существует физически в ожидаемом месте).

Воспроизведение:

```go
s, err := store.OpenSQLite("")
// err == nil, s — рабочий Store поверх анонимной временной БД
```

или конфигом с пустым `path = ""` в секции `[store]`.

## Что сделать

Выбрать и реализовать одно (или оба, если решишь, что это оправдано) из:

- **Валидация конфига.** `StoreConfig.Validate` для `driver="sqlite"` (и пустого
  `Driver`) отклоняет пустой `Path` явной ошибкой (`fmt.Errorf`, в духе уже
  существующей ветки `driver="postgres"` в той же функции) — это ловит опечатку в
  конфиге на `config.Load`, до открытия хранилища.
- **Явная ошибка в сборке DSN/открытии.** `sqliteDSN`/`OpenSQLite`
  (`internal/memory/store/sqlite.go`) отклоняют пустой `path` до `sql.Open` —
  страхует прямых вызывающих `store.OpenSQLite`/`store.Open`, которые не проходят
  через `config.Load` (тесты, будущий код), не только конфиг-путь.

Соответствующий тест (в стиле уже существующих `TestSqliteDSN_*`/`TestOpenSQLite_*`
из задачи 12.2 или `Validate`-тестов `internal/config`).

## Границы

- Не менять поведение для непустых путей — ни экранирование (`escapeSQLiteURIPath`),
  ни `expandHome`.
- Не трогать `driver="postgres"` ветку `Validate`.
- Если для реального in-memory режима (`:memory:`/`file::memory:`) когда-нибудь
  понадобится осознанная поддержка — это отдельная задача, не смешивать с этой:
  здесь речь только о том, что ПУСТАЯ строка не должна тихо давать тот же эффект,
  что специальный синтаксис.

## Критерий приёмки

`CGO_ENABLED=1 go build -tags sqlite_fts5 ./...` и
`CGO_ENABLED=1 go test -tags sqlite_fts5 -count=1 ./...` зелёные; пустой
`store.path` для sqlite-бэкенда даёт явную ошибку (на этапе `config.Load` и/или
`OpenSQLite`), а не молча работающий `Store` поверх одноразовой временной БД;
существующие сценарии с непустыми путями (включая относительные и `~`) не
регрессируют.
