# Задача 7.2 — Ambient memory: хуки харнесса через `memo hook` + генерация в `init`

**Статус:** ✅ выполнена
**Этап:** 7 (Ambient memory — хуки) · **Область:** `cmd/memo` (подкоманда `hook`,
расширение `init`)
**Зависимости:** **7.1 (CLI)** — хук технически является one-shot CLI-вызовом.

## Контекст

Главная боль агентной памяти: агент по своей воле забывает и сохранять, и доставать —
сейчас догфудинг держится на том, что скилл напоминает звать `memory_recall` вручную.
Хуки харнесса (Claude Code: `SessionStart`, `UserPromptSubmit`, `Stop`) снимают это:
харнесс сам дёргает память на событиях жизненного цикла, бриф вклеивается в контекст
без участия агента — память становится **ambient**.

Механика Claude Code: хук — это shell-команда из `.claude/settings.json`; на stdin ей
приходит JSON события, **stdout добавляется в контекст сессии** (для SessionStart и
UserPromptSubmit), ненулевой exit-код может блокировать работу — поэтому железное
правило: **хук памяти никогда не ломает сессию** (любая ошибка → пустой stdout, exit 0).

## Что сделать

### Часть A — подкоманда `memo hook`

Новый файл `cmd/memo/hook.go` (+ тест). Синтаксис: `memo hook -event <name>
[-config path]`. Читает JSON события из stdin (поля по событию: `session_id`, `cwd`,
`prompt` — распарсить мягко, неизвестные поля игнорировать).

- **`-event session-start`**: recall фиксированным запросом «состояние проекта,
  договорённости, следующие шаги, грабли» + scopes по дефолту инстанса; kinds — все;
  бюджет — из конфига (или уменьшенный, напр. 600). Выдача в stdout с заголовком
  `## Долговременная память проекта (авто-recall)` — чтобы в контексте было видно
  происхождение. Пустая память → пустой stdout.
- **`-event prompt-submit`**: query = поле `prompt` из stdin-JSON; порог — если prompt
  короче ~15 символов, ничего не делать (мусорные запросы). Уменьшенный бюджет
  (напр. 400): вызывается на каждом сообщении, нельзя раздувать контекст.
- **Оба события**: summarize выключен (латентность), логи только в stderr,
  **любая ошибка (нет конфига, нет БД, битый stdin) → пустой stdout, exit 0**.
  Это осознанное отступление от fail-fast: хук — фоновая роскошь, не критический путь.

Реализация — тонкая обёртка над recall-путём из 7.1 (общий приватный хелпер в
`cmd/memo`; не копировать логику).

### Часть B — генерация хуков в `memo init`

Расширить интерактивный сетап (`init.go`): после существующих шагов — вопрос
«Подключить автоматический recall через хуки Claude Code?» с вариантами:
только session-start (дефолт) / session-start + prompt-submit / нет.

- Пишет в `.claude/settings.json` секцию `hooks` с командой
  `<абсолютный путь bin/memo> hook -event session-start -config <путь toml>`.
- **Merge, не перезапись**: существующий settings.json парсится, добавляются только
  недостающие хуки; чужие ключи не трогаются; повторный init идемпотентен
  (та же команда не дублируется). Битый JSON → внятная ошибка, файл не трогать.
- Для opencode (второй поддерживаемый харнесс) — если аналога хуков нет, честно
  написать в выводе init, что ambient-режим доступен только для Claude Code.

## Границы

- Только `cmd/memo` (hook.go, init.go, skill.go, справка). `internal/*`, MCP-схемы,

- Не изобретать свой формат событий — только фактический JSON хуков Claude Code
  (сверить поля по актуальной документации при реализации).

## Тесты

- `hook_test.go`: session-start на scratch-БД → бриф с заголовком в stdout;
  prompt-submit берёт query из stdin-JSON; короткий prompt → пустой stdout;
  отсутствующая БД/битый stdin/битый конфиг → пустой stdout + exit 0 (главный
  инвариант — проверить все три); логи не попадают в stdout.
- `init_test.go` (дополнить): merge hooks в существующий settings.json не теряет
  чужие ключи; идемпотентность повторного init; битый JSON → ошибка без записи.

## Критерий приёмки

- Билд/vet/тесты `-tags sqlite_fts5` зелёные.
- e2e: в тестовом проекте `memo init` с хуками → новая сессия Claude Code
  стартует с блоком «Долговременная память проекта» в контексте; при удалённой БД
  сессия стартует без ошибок (хук молчит).
