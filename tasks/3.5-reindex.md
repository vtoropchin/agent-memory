# Задача 3.5 — Reindex при смене модели + досчёт очереди

**Статус:** ⏳ ожидает 3.1, 3.2 (3.3 — для ListMissingVectors)
**Этап:** 3 (Embedder + гибрид) · **Пакет:** `internal/memory/maint`
**Зависимости:** 3.2 (vec-методы Store), 3.3 (`ListMissingVectors`)

## Контекст

DESIGN.md §9: векторы разных моделей несравнимы; при старте сверяем `embed_meta` с текущей
моделью — не совпало → пересоздаём vec-таблицу с новым dim и перегоняем весь content через
новый Embedder; пока идёт — recall деградирует до FTS5 (это происходит само: vec-таблица
наполняется постепенно). §11: reindex — фоновый джоб.

## Что сделать

1. Новый файл `internal/memory/maint/reindex.go`:
   - Тип `Reindexer` (Store, `embed.Embedder`), конструктор `NewReindexer`.
   - `CheckAndReindex(ctx) (ReindexResult, error)`:
     a. `embedder.Dim() == 0` (Noop) → ничего не делать, пустой результат.
     b. `store.EmbedMeta(ctx)`: если model/dim совпадают с текущим Embedder — reindex не
        нужен, перейти к досчёту (шаг d).
     c. Не совпали (или meta пустая): `ResetVectorIndex(model, dim)`, затем
        `AllForReindex` и батчами по 64: `Embed(ctx, contents)` → `PutVector` каждому.
        Ошибка эмбеддинга батча → лог, батч пропустить, продолжить (недоэмбеженное
        доберёт следующий досчёт).
     d. Досчёт очереди: `ListMissingVectors(ctx, 256)` циклом, теми же батчами, пока
        список не пуст или не случилась ошибка (тогда лог и выход без ошибки наружу —
        деградация §15; наружу ошибки только от ResetVectorIndex).
   - `ReindexResult{Reindexed bool, Embedded, Failed int}`.
2. Отмена по ctx уважается между батчами (проверять `ctx.Err()`).
3. Тесты с фейковым Embedder (детерминированные векторы, управляемые ошибки) и реальным
   in-memory store: пустая meta → полный reindex, meta записана; совпадающая meta →
   reindex не выполняется, но досчитываются недостающие векторы; смена модели →
   пересоздание и перегон; ошибка Embed одного батча не роняет остальные; Noop → no-op.

## Границы

Не трогать: `cmd/memoryd` (запуск при старте — задача 3.6), `recall`, `write`, `mcp`,
`config`. Планировщик по расписанию — задача 4.3.
