# Задача 3.2 — sqlite-vec в Store (векторный индекс)

**Статус:** ⏳ ожидает MP-1
**Этап:** 3 (Embedder + гибрид) · **Пакет:** `internal/memory/store` · **Зависимости:** MP-1
(общий scope-предикат уже в `SearchLexical`)

## Контекст

DESIGN.md §4 (закомментированная схема `memories_vec` + `embed_meta`), §6 (vec-методы
Store), §9 (reindex при смене модели). Сейчас в `sqlite.go` методы `SearchVector`,
`ResetVectorIndex`, `PutVector`, `EmbedMeta`, `AllForReindex` — заглушки Этапа 1.
Таблица `embed_meta` уже создаётся. Драйвер — `mattn/go-sqlite3` (CGO).

## Что сделать

1. Подключить биндинг `github.com/asg017/sqlite-vec-go-bindings/cgo`: перед открытием
   соединения вызвать `sqlite_vec.Auto()` (регистрирует расширение для всех новых
   соединений). Сверься с README биндинга (Context7: библиотека `sqlite-vec`) насчёт
   точного API для mattn/go-sqlite3 и сериализации векторов
   (`sqlite_vec.SerializeFloat32`).
2. Реализовать методы (сигнатуры в `store.go` НЕ менять):
   - `ResetVectorIndex(ctx, model, dim)`: `DROP TABLE IF EXISTS memories_vec`; создать
     `CREATE VIRTUAL TABLE memories_vec USING vec0(memory_id TEXT PRIMARY KEY,
     embedding float[<dim>] distance_metric=cosine)`; upsert единственной строки
     `embed_meta (id=1, model, dim)`. В транзакции.
   - `EmbedMeta(ctx)`: чтение `embed_meta`; отсутствие строки → `("", 0, nil)`.
   - `PutVector(ctx, id, vec)`: INSERT OR REPLACE в `memories_vec`. Если таблицы нет →
     внятная ошибка.
   - `SearchVector(ctx, vec, q)`: KNN `SELECT memory_id, distance FROM memories_vec
     WHERE embedding MATCH ? AND k = ?` (k из q.Limit, дефолт как в SearchLexical);
     затем join с `memories` и те же фильтры, что в `SearchLexical`: kinds, since_ts,
     `superseded_by IS NULL` и **scope через общий хелпер `scopePredicate` из MP-1**
     (набор `Query.Scopes`, НЕ одиночный scope — переиспользуй тот же хелпер, не дублируй).
     Кандидаты: `Score = 1/(1+distance)`,
     `Source = "vector"`, отсортированы по distance. **Если `memories_vec` не существует
     (Embedder выключен) → вернуть `nil, nil` без ошибки** (деградация §15).
   - `AllForReindex(ctx)`: все записи без `superseded_by` (с tags/links).
3. Тесты в `store_test.go`: ResetVectorIndex создаёт таблицу и пишет meta (повторный
   вызов с другим dim пересоздаёт); PutVector+SearchVector возвращает ближайших в
   правильном порядке с фильтром по **набору scope** (`Query.Scopes` — свой проект виден,
   чужой нет) и без superseded; SearchVector без
   vec-таблицы → пусто без ошибки; EmbedMeta до/после Reset; AllForReindex не отдаёт
   superseded.

## Границы

не менять. Новая зависимость разрешена только `sqlite-vec-go-bindings`.
