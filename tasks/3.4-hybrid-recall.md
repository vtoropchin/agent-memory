# Задача 3.4 — Гибридный recall (FTS5 + вектор через RRF)

**Статус:** ✅ выполнена (2026-07-11) — билд чист, `go test -tags sqlite_fts5 -count=1 ./...` зелёный целиком.
**Этап:** 3 (Embedder + гибрид) · **Пакет:** `internal/memory/recall`
**Зависимости:** 3.2 (SearchVector работает), MP-1 (`Query.Scopes`); интерфейс `Embedder` — в репо

## Контекст

DESIGN.md §8: кандидаты = FTS5 + vec (если включён), слияние — RRF (k≈60). RRF в
`recall.go` уже реализован и готов ко второму источнику. `store.SearchVector` возвращает
кандидатов с `Source="vector"`; при выключенном векторе — пусто без ошибки.

## Что сделать

1. `recall.Recaller` получает зависимость `embed.Embedder` (расширить конструктор `New`;
   поправить все места вызова — тесты, `cmd/memo` — передав `embed.NewNoop()`).
2. В `Recall`: если `embedder.Dim() > 0` и текст запроса непуст — `Embed(ctx, [q.Text])`,
   затем `store.SearchVector(ctx, vec, q)`; список кандидатов вектора идёт вторым
   источником в существующий RRF рядом с лексическим. Ошибка Embed или SearchVector →
   лог в stderr, продолжить только с FTS (деградация §15, не ошибка). Noop → вектор
   не зовётся вовсе.
3. Дедупликация между источниками — по id внутри RRF (проверь, что текущая реализация
   RRF корректно суммирует вклад обоих источников для одного id; если нет — поправь).
   **Scope:** и лексический, и векторный источники получают один и тот же `q` (с уже
   разрешённым `Query.Scopes` — разрешение делает MP-2, не эта задача). Не хардкодить
   scope-логику в recall; просто прокинуть `q` в оба `Search*`.
4. Тесты: фейковый Embedder + реальный in-memory store с vec-таблицей (см. тесты 3.2):
   запись, находимая только вектором (перефразировка без общих токенов), попадает в бриф;
   запись, находимая обоими источниками, ранжируется выше найденной одним (свойство RRF);
   ошибка Embed → бриф строится из FTS без ошибки; Noop → SearchVector не вызывается
   (счётчик на фейковом store не нужен — достаточно фейкового Embedder со счётчиком).

## Границы

Не трогать: `write`, `mcp`, `store` (кроме случая бага в RRF — тогда только recall.go),
`embed`, `cmd/memo` (кроме вызова конструктора), `config`.
