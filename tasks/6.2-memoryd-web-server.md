# Задача 6.2 — Подкоманда `memo web`: HTTP-сервер + JSON API

**Статус:** ✅ выполнена
**Этап:** 6 (Web-морда) · **Область:** `cmd/memo` (новые `web.go`/`web_test.go` + врезка в `main.go` + embed каталога `cmd/memo/web/`)
**Зависимости:** 6.1 (методы `Store.List`/`Store.Stats` + типы `BrowseFilter`/`Stats`)

## Контекст

Даём read-only просмотр памяти через браузер. Форма — **подкоманда `memo web`** (решение
пользователя), по образцу уже существующей `memo init` (`cmd/memo/init.go`,
диспетчеризуется в `main.go` до серверных флагов). Это отдельный режим одного бинаря: он НЕ
поднимает MCP-stdio, а открывает тот же общий файл БД (`~/.agentmemory/memory.db`, DESIGN.md
§2.1: WAL + busy_timeout → параллельные читатели безопасны, memo/memimport уже так сосуществуют)
и отдаёт HTTP: JSON API + статический фронтенд (сам фронтенд — задача 6.3).

**Read-only:** обработчики зовут ТОЛЬКО read-методы store (`List`/`Stats`/`Get`/`Neighbors`/
`SearchLexical`). Никаких `Put`/`Supersede`/`Update` — правок из UI в этой версии нет.

## Что сделать

Только пакет `cmd/memo`: новый `web.go` (+ `web_test.go`), врезка диспетчеризации в `main.go`,
embed каталога статики. Доменные пакеты не трогать (кроме вызова новых read-методов из 6.1).

### 1. Диспетчеризация в `main.go`

Рядом с веткой `init` (перед разбором серверных флагов и `log.SetOutput`), симметрично:
```go
if len(os.Args) >= 2 && os.Args[1] == "web" {
    if err := runWeb(os.Args[2:], os.Stdout); err != nil {
        fmt.Fprintf(os.Stderr, "memo web: %v\n", err)
        os.Exit(1)
    }
    return
}
```
Серверный путь (`memo`, `-config`, `-db`) и `init` — без изменений.

### 2. `runWeb` (`web.go`)

Флаги (свой `flag.NewFlagSet("web", flag.ExitOnError)`):
- `-addr string` — адрес прослушивания, дефолт **`127.0.0.1:7070`** (только localhost — морда
  показывает всю память, наружу по умолчанию не выставляем).
- `-config string` — путь к TOML-конфигу (как у сервера; для получения `store.path`).
- `-db string` — переопределить путь файла БД (как у сервера; приоритетнее конфига).

Логика старта (переиспользовать то, что уже делает `run()` в main.go):
- `config.Load(-config)`; `-db` переопределяет `cfg.Store.Path`. `.env`/reasoner/embedder НЕ
  нужны — морда только читает store лексически (без ollama/DeepSeek).
- `store.Open(cfg.Store.Path)`; `defer s.Close()`.
- Собрать `http.Server{Addr, Handler: mux}`; поднять; graceful shutdown по SIGINT/SIGTERM
  (`signal.NotifyContext` + `srv.Shutdown(ctx)`).
- Это CLI-режим (не MCP) — писать в **stdout** приветствие: `слушаю http://<addr> (Ctrl+C — стоп)`,
  логи — в stderr.

### 3. Роутинг (`net/http.ServeMux`, method-aware паттерны Go 1.22+)

Все под `/api/`, отдают `application/json; charset=utf-8`. Ошибки — JSON `{"error":"..."}` с
корректным статусом (400 на плохие параметры, 404 на неизвестный id, 500 на ошибку store).

- **`GET /api/stats`** → `Store.Stats` →
  `{"total":N,"superseded":N,"byScope":{"project:x":N,...},"byKind":{"semantic":N,...}}`
- **`GET /api/memories`** — browse. Query-параметры:
  - `scope` (повторяемый: `?scope=a&scope=b`) → `BrowseFilter.Scopes`
  - `kind` (повторяемый) → `BrowseFilter.Kinds`
  - `superseded=1` → `IncludeSuperseded=true`
  - `limit` (int, дефолт 50, потолок напр. 200), `offset` (int, дефолт 0)
  - Ответ: `{"items":[<memoryDTO>...],"total":N,"limit":N,"offset":N}`
- **`GET /api/memories/{id}`** — карточка. `Store.Get(id)` (404 если не найдено) +
  `Store.Neighbors(id)`. Ответ: `{"memory":<memoryDTO>,"neighbors":[<memoryDTO>...]}`
- **`GET /api/search`** — лексический поиск. Параметры: `q` (обязателен; пустой → 400),
  опц. `scope`(повторяемый)/`kind`(повторяемый)/`limit`. Собрать `memory.Query{Text:q,
  Scopes:..., Kinds:..., Limit:...}` → `Store.SearchLexical`. Ответ:
  `{"items":[{...memoryDTO, "score":F, "source":"lexical"}...]}`. Гибридный/векторный поиск —
  вне этой версии (требует embedder/ollama); зафиксировать в комментарии как возможное
  расширение.
- **`GET /`** и статика — из embed.FS (см. п.4).

### 4. DTO и сериализация

Не отдавать `memory.Memory` напрямую (в нём указатели/внутренние поля) — объявить `memoryDTO`
с явными JSON-тегами и нормализацией nullable-полей (`*string`/`*int64` → значение или `null`):
```
id, kind, scope, content, summary, importance,
createdAt, updatedAt, accessedAt, accessCount, supersededBy, source,
tags[], links[{dst, rel}]
```
(имена полей camelCase — их потребляет фронтенд 6.3). Хелпер `toDTO(memory.Memory) memoryDTO`.

### 5. Embed статики

- Каталог `cmd/memo/web/` со статикой (index.html + app.js — наполняет 6.3). Чтобы 6.2
  собиралась и запускалась независимо, положить **плейсхолдер** `web/index.html` (заглушка
  «web-морда: фронтенд — задача 6.3», можно с проверочной ссылкой на `/api/stats`).
- `//go:embed web` → `embed.FS`; отдавать через `http.FileServerFS(sub)` на `/`. API-роуты
  регистрировать ДО файлового хендлера, чтобы `/api/*` не перехватывался статикой.

## Тесты (`web_test.go`, через `httptest` поверх временного store)

Наполнить временный store через `store.Open` + прямые `Put` (или переиспользовать тест-хелпер),
поднять `http.Handler` из `runWeb`-сборки (вынести конструктор мультиплексора в тестируемую
функцию `newWebHandler(s store.Store) http.Handler`) и бить `httptest`:
- `/api/stats` — корректные счётчики (JSON round-trip в `Stats`-подобную структуру).
- `/api/memories` — пагинация (limit/offset, total), фильтры scope/kind, `superseded=1`.
- `/api/memories/{id}` — существующий id → карточка с tags/links + neighbors; неизвестный → 404.
- `/api/search?q=` — находит по content; пустой `q` → 400.
- DTO: nullable-поля (`summary`/`accessedAt`/`supersededBy`/`source` = null при отсутствии),
  camelCase-ключи, links `{dst,rel}`.
- `/api/*` не перехватывается статикой; неизвестный API-путь → 404.

- Контракт API (пути + форма JSON выше) зафиксирован — на него опирается фронтенд 6.3.
