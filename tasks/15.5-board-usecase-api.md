# Задача 15.5 — Вариант использования «доска» (`internal/memory/board`) + JSON API морды

**Статус:** ⬜ ожидает
**Этап:** 15 (Kanban-доска задач, DESIGN.md §14 Этап 15) · **Область:**
новый пакет `internal/memory/board`, `internal/memory/store` (sqlite + postgres:
`ListTasks`), `internal/memory/arch_test.go`, `cmd/memo/web.go`, `cmd/memo/web_test.go`
**Зависимости:** 15.1 (модель), 15.3 (хелперы графа), 15.4 (`LiveBlockers`,
`GetMany`, `Unlinks`). Фронтенд — 15.6, после фиксации контракта API отсюда.

## Контекст

Доска — **вариант использования, не хендлер** (DESIGN.md §14 Этап 15, по итогам
арх-ревью): сборка колонок, вычисление `Blocked`/`Parent`/`Progress` — логика,
которая должна тестироваться без HTTP и переиспользоваться отложенными
потребителями (`memo task` в CLI, MCP «покажи доску»). Web-морда — тонкая
доставка: `GET /api/board` и расширенный `PATCH /api/memories/{id}`.

Ключевые решения:

- Пакет `board` **не импортирует `store`**: объявляет свой узкий порт `Source`
  (`ListTasks`, `GetMany`), который `store` удовлетворяет структурно → `board`
  даёт **0** в `TestDependencyRule`, а не наследует базовую линию 5 с
  драйверами БД. Единственные импорты ядра — `agentmemory/internal/memory`.
- `Store.ListTasks(ctx, scopes)` — специализированный read (по образцу
  `ListEpisodicForDecay`): все живые `kind=task` в scopes, с Tags и Links,
  без пагинации. `List`/`BrowseFilter` не растягиваются флагами.
- Колонки — из `memory.Statuses` (порядок = жизненный цикл), второго перечня
  нет. Сортировка карточек в колонке: `Importance` ↓, затем `UpdatedAt` ↓.
  Порядок «руками» — отложен.
- Колонка `done` усечена: `DoneLimit` (дефолт 30) самых свежих по `UpdatedAt`,
  в ответе — `doneTotal`, «показать ещё» фронт делает повторным запросом с
  бо́льшим `doneLimit`. Остальные колонки — целиком.
- Кросс-scope блокеры (не попавшие в `ListTasks`) догружаются `GetMany` по id.
- Web-инвариант §12 (обновлённый): из браузера не меняются `content`/`kind`/
  `scope`/`summary`, нет создания записей и hard DELETE; PATCH — whitelist-DTO
  1:1 в `write.UpdateInput` **без собственной логики**; доменные ошибки
  маппятся `errors.Is` в HTTP-статусы, а не в 500.

## Что сделать

### A — store: `ListTasks`

- `Store.ListTasks(ctx, scopes []string) ([]memory.Memory, error)`: `kind =
  'task' AND superseded_by IS NULL` [+ `scope IN (...)` при непустом scopes],
  Tags и Links батчами (`loadTagsBatch`, `loadLinksBatch` из 15.3),
  сортировка по `updated_at DESC`. SQLite + PostgreSQL. Годок в `store.go`.

### B — пакет `internal/memory/board`

- `board.go`:
  ```go
  type Source interface {
      ListTasks(ctx context.Context, scopes []string) ([]memory.Memory, error)
      GetMany(ctx context.Context, ids []string) ([]memory.Memory, error)
  }
  type Filter struct {
      Scopes   []string
      Types    []memory.TaskType // пусто — все
      ParentID string            // только дети этого эпика/истории (по ParentOf)
      Branch, Workflow string    // точное совпадение; пусто — без фильтра
      Tag      string            // хотя бы этот тег
      DoneLimit int              // <=0 → defaultDoneLimit (30)
  }
  type Card struct {
      Memory    memory.Memory
      Blocked   bool
      BlockedBy []Ref            // живые блокеры (id, summary, status)
      Parent    *Ref             // ближайший родитель по part_of
      Progress  *Progress        // только для epic/story с детьми: {Done, Total}
  }
  type Column struct { Status memory.Status; Cards []Card; Total int } // Total ≠ len(Cards) только у done
  type Board struct { Columns []Column }
  func Build(ctx context.Context, src Source, f Filter) (Board, error)
  ```
- Алгоритм `Build`: `ListTasks(scopes)` → индекс по id → обратный индекс
  детей (`ChildrenOf`) и `Progress` для каждого родителя (считается по **всем**
  живым задачам scope, до фильтров — прогресс эпика не зависит от того, что
  показано) → блокеры: `BlockerIDs` всех задач, отсутствующие в индексе —
  `GetMany` → `LiveBlockers` → `Blocked`/`BlockedBy` → применить `Filter`
  (типы/родитель/ветка/workflow/тег) → разложить по `memory.Statuses` →
  сортировка → усечение `done`. Родитель для карточки берётся из индекса; если
  родитель вне scopes — `Ref` только с id (summary пустой).
- Тесты `board_test.go` с **in-memory fake `Source`** (без SQLite): порядок
  колонок; сортировка; усечение `done` и `Total`; `Blocked` с блокером в
  scope и вне scope (через `GetMany`); блокер `done` не блокирует; `Parent`/
  `Progress`; каждый фильтр; пустая доска.
- `internal/memory/arch_test.go`: добавить `"agentmemory/internal/memory/board": 0`
  в `baseline` — тест обязан падать, если `board` когда-нибудь импортирует
  `store`.

### C — web API: `cmd/memo/web.go`

- `GET /api/board?scope=…(повторяемый)&type=…&parent=…&branch=…&workflow=…&tag=…&doneLimit=N`
  → `board.Build` через `store` (структурно удовлетворяет `Source`); ответ —
  DTO: `{columns:[{status, total, cards:[{id, summary, type, status,
  importance, tags, branch, workflow, updatedAt, blocked, blockedBy:[{id,
  summary, status}], parent:{id, summary}|null, progress:{done,total}|null}]}]}`.
  `content` в карточку доски не отдаётся (карточка записи — по `GET
  /api/memories/{id}`). Неизвестный `type` → 400.
- `PATCH /api/memories/{id}`: `patchMemoryRequest` += `Status *string`, `Type
  *string`, `Branch *string`, `Workflow *string`, `Links []{id, rel}`,
  `Unlinks []{id, rel}` — 1:1 в `write.UpdateInput`; обновить
  `patchMemoryAllowedFields`. Маппинг ошибок (`errors.Is`): `ErrTaskBlocked` →
  409 с телом `{error, blockers:[{id, summary}]}`; `ErrUnknownStatus`/
  `ErrUnknownTaskType`/`ErrStatusNotApplicable`/`ErrTaskFieldNotApplicable`/
  `ErrBlockerNotTask` → 400; тумстоун → 409 (как сейчас). Ни одной проверки
  доменного правила в `web.go`.
- Пикеры фронта («выбрать блокер/родителя») — отдельного эндпоинта НЕ
  делать: фронт использует существующий `GET /api/search?q=…&mode=lexical` с
  уже существующим параметром `kind=task` (`web.go`: `Kinds: nonEmpty(q["kind"])`).
- DESIGN.md §12: описание `GET /api/board` и расширенного PATCH — синхронизировать
  (короткий абзац по образцу `/api/search`).

## Границы

- НЕ делать фронтенд (15.6), не менять `write`/`recall`/`mcp`, схему БД.
- `board` не знает про HTTP, JSON и `store`.
- Никакой логики блокировки/иерархии в `web.go` — только маппинг.

## Тесты

- `board_test.go` (см. B) — быстрые, без БД.
- `store`: `ListTasks` — только живые задачи scope с Links/Tags; пустые scopes
  — все.
- `web_test.go` (httptest поверх временного SQLite): `/api/board` — форма
  ответа, фильтры, `doneLimit`/`total`; PATCH `status: doing` у заблокированной
  → 409 с блокерами; PATCH `status: "blocked"` → 400; PATCH `unlinks` снимает
  блокировку и следующий PATCH `doing` → 200; PATCH `content` по-прежнему 400.

## Критерий приёмки

- Билд/vet/тесты зелёные; `TestDependencyRule`: `board` = 0, остальные без
  изменений.
- `curl` к живому `memo web` на копии реальной БД: `/api/board?scope=project:…`
  отдаёт 7 колонок, эпики с `progress`, заблокированные с `blockedBy`; PATCH
  переводит карточку и возвращает 409 на заблокированной.
- Финализация по циклу `/dev`; статус в файле и `tasks/README.md`.
