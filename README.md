# AgentMemory

Долговременная память для ИИ-агентов на Go. Агент во время работы сохраняет атомарные
факты, события и процедуры, а в другой сессии — своей или чужой — запрашивает их обратно
по смыслу и получает компактный Markdown-бриф, обрезанный под бюджет токенов, а не сырую
выдачу top-k.

Хранилище — один файл SQLite (метаданные + полнотекстовый индекс FTS5 + опциональный
вектор через `sqlite-vec`). Агент общается с памятью через MCP по stdio.

## Зачем это

- Сохранил факт в одной сессии — достал по смыслу в другой, без ручного копирования в промпт.
- Recall отдаёт не сырьё, а ранжированный и обрезанный под токен-бюджет бриф.
- Память не превращается в свалку: дедупликация при записи, устаревание episodic-фактов,
  консолидация в semantic — фоновыми джобами.
- Работает локально: SQLite-файл, без обязательных внешних сервисов. Вектор (ollama) и
  суммаризация (DeepSeek) — опциональные слои: недоступны — recall деградирует до FTS5,
  а не падает.
- Подключается к проекту одной командой (`memoryd init`), которая сама раскладывает
  MCP-конфиг и инструкцию для агента.

## Быстрый старт

Предпосылки:

- Go 1.26+
- C-компилятор (CGO обязателен — `mattn/go-sqlite3` собирается с тегом `sqlite_fts5`)
- опционально: [ollama](https://ollama.com) с моделью `bge-m3` для векторного поиска
- опционально: ключ DeepSeek (`DEEPSEEK_API_KEY`) для суммаризации и консолидации памяти

Без ollama и DeepSeek память тоже работает — на чистом FTS5, без суммаризации выдачи.

Собери и поставь бинарь себе в `~/.local/bin` (без sudo):

```sh
make install
```

Если `~/.local/bin` не в `PATH`, `make install` подскажет строку для `~/.zshrc`.

Подключи память к своему проекту — из корня проекта, куда её ставишь:

```sh
memoryd init
```

В интерактивном режиме спросит имя проекта, агентское приложение (`claude` или
`opencode`), адрес и модель ollama, путь к файлу БД и, по желанию, ключ DeepSeek — и
разложит:

- MCP-конфиг (`.mcp.json` для Claude Code или `opencode.json` для opencode);
- скил-инструкцию «Протокол работы с памятью» (см. [раздел ниже](#скил-протокол-работы-с-памятью));
- `agentmemory.toml` со введёнными настройками;
- `.env` с ключом DeepSeek (если ввёл) — с правами `0600` и строкой в `.gitignore`.

Для неинтерактивного запуска (CI, скрипты) — флагами и `-no-input`:

```sh
memoryd init -project myproject -agent claude -no-input
```

После этого агентское приложение само поднимает `memoryd` как MCP-сервер `agentmemory`.
Агенту в системный промпт/скил уже прописано: `memory_recall` — в начале задачи (подтянуть
контекст), `memory_save` — по ходу работы, когда появляется факт стоит запомнить.

Посмотреть, что накопилось, глазами — read-only web-морда:

```sh
memoryd web
```

и открыть `http://127.0.0.1:7070` — дашборд статистики, список записей с фильтрами по
scope/kind, карточка записи с соседями по графу и лексический поиск. Слушает только
localhost.

## Скил «Протокол работы с памятью»

Мало дать агенту четыре MCP-инструмента — он должен знать, когда их трогать. Поэтому
`memoryd init`, кроме конфига, кладёт в проект скил — файл `SKILL.md` с `name: memoryd`:

- Claude Code — `.claude/skills/memoryd/SKILL.md`
- opencode — `.opencode/skills/memoryd/SKILL.md`

Тело скила одно для всех приложений (различаются только путь файла и формат MCP-конфига),
и агентское приложение подхватывает его само — по полю `description` оно понимает, когда
протокол релевантен. Что внутри:

- **Когда звать.** `memory_recall` — в начале любой задачи, чтобы подтянуть решения и
  прогресс прошлых сессий. `memory_save` — по ходу и в конце, по одному атомарному факту
  (1–3 предложения) за вызов. `memory_update` — когда факт изменился. `memory_forget` —
  когда устарел или ошибочен (мягкое удаление).
- **Правила scope.** `save` без явного scope пишет в `project:<name>`; `recall` без scope
  ищет в `project:<name>` + `user:*`; явный scope перекрывает дефолт. Проектные
  факты, решения и грабли — в `project:<name>`; общие привычки пользователя — в `user:*`.
- **Если сервера нет.** Когда инструменты `memory_*` в сессии не видны (MCP-сервер не
  поднят или не одобрен приложением) или reasoner/embedder деградировали — продолжать
  задачу без долговременной памяти, предупредив об этом.

Этот скил — обобщённая версия того, по которому сам AgentMemory ведёт свою разработку
(`.claude/skills/dev`): проект хранит рабочую память в собственном `memoryd` и тем самым
проверяет себя на себе.

## Использование

Бинарь `memoryd` — несколько режимов, различаются первым аргументом:

| Команда | Что делает |
|---|---|
| `memoryd [-config <path>] [-db <path>]` | MCP-сервер по stdio (режим по умолчанию) |
| `memoryd init [флаги]` | установщик: раскладывает MCP-конфиг, скил, `agentmemory.toml`, `.env` в проект |
| `memoryd web [флаги]` | HTTP-морда для просмотра памяти в браузере (read-only + мягкое удаление) |
| `memoryd doctor [флаги]` | read-only диагностика: в каком режиме реально работает память, ничего не пишет |
| `memoryd export [флаги]` | экспорт памяти в переносимый JSONL-бэкап (полный или по `-scopes`) |
| `memoryd import [флаги] file.jsonl` | восстановление из JSONL-бэкапа с сохранением id и таймстампов |

`memoryd --help` (`-h`/`help`) печатает сводку; `memoryd init -h`, `memoryd web -h`,
`memoryd doctor -h`, `memoryd export -h`, `memoryd import -h` и т.д. — флаги конкретной подкоманды.

Флаги режима сервера:

| Флаг | Значение |
|---|---|
| `-config <path>` | путь к TOML-конфигу (опционально) |
| `-db <path>` | путь к SQLite-файлу, переопределяет `store.path` из конфига |

Ключ DeepSeek берётся из `DEEPSEEK_API_KEY` в окружении или из `.env` рядом с конфигом.

Флаги `memoryd init`:

| Флаг | Значение |
|---|---|
| `-project` | имя проекта (дефолт — базовое имя каталога `-dir`) |
| `-dir` | каталог, в который скаффолдить артефакты (дефолт `.`) |
| `-force` | перезаписывать существующие файлы |
| `-agent` | `claude` или `opencode` (дефолт `claude`) |
| `-ollama-url` | base URL ollama (дефолт `http://localhost:11434`) |
| `-ollama-model` | модель эмбеддингов ollama (дефолт `bge-m3`) |
| `-store` | путь к файлу SQLite (дефолт `~/.agentmemory/memory.db`) |
| `-deepseek-key` | ключ DeepSeek — пишется в `<dir>/.env` (попадёт в историю shell, если задан флагом) |
| `-no-input` | не спрашивать интерактивно — только флаги и дефолты |

Флаги `memoryd web`:

| Флаг | Значение |
|---|---|
| `-addr` | адрес прослушивания (дефолт `127.0.0.1:7070`) |
| `-config` | путь к TOML-конфигу (опционально) |
| `-db` | путь к SQLite-файлу, переопределяет `store.path` из конфига |

Флаги `memoryd doctor`:

| Флаг | Значение |
|---|---|
| `-config` | путь к TOML-конфигу (опционально) |
| `-db` | путь к SQLite-файлу, переопределяет `store.path` из конфига |
| `-json` | машиночитаемый JSON вместо человекочитаемого списка секций |
| `-live` | выполнить пробный запрос к DeepSeek (стоит денег; по умолчанию выключено) |

`memoryd doctor` отвечает на вопрос «в каком режиме реально работает память и всё ли
с ней хорошо» одной командой, строго read-only (не пишет в БД, не чинит): 7 секций
(конфиг, БД + `PRAGMA quick_check`, счётчики записей, векторный индекс vs конфиг
эмбеддера, живость embedder'а пробным эмбеддингом, наличие ключа/провайдера Reasoner,
итог), каждая помечена ✅/⚠️/❌. Полезно после смены модели эмбеддера, при подозрении
на остановленную ollama или просто чтобы понять, почему recall выглядит бедным.
Код выхода: `0` — здоров или деградирован (только ⚠️), `1` — есть хотя бы одна ❌
(скриптуемо, напр. в CI/крон-проверке).

### Бэкап и перенос

Память живёт в одном файле SQLite — `memoryd export`/`memoryd import` дают штатный способ
её забэкапить, продиффать или перенести на другую машину/в другой проект.

Флаги `memoryd export`:

| Флаг | Значение |
|---|---|
| `-config` | путь к TOML-конфигу (опционально) |
| `-db` | путь к SQLite-файлу, переопределяет `store.path` из конфига |
| `-o` | путь к выходному файлу (пусто — stdout, пайпабельно) |
| `-scopes` | пространства через запятую для частичного экспорта (пусто — вся БД) |

Флаги `memoryd import`:

| Флаг | Значение |
|---|---|
| `-config` | путь к TOML-конфигу (опционально) |
| `-db` | путь к SQLite-файлу, переопределяет `store.path` из конфига |
| `-dry-run` | только разобрать файл и напечатать отчёт; БД не открывается вовсе |
| `-overwrite` | заменять записи с конфликтующим id (по умолчанию — пропуск) |
| `-rescope` | перенос scope при импорте: `old=new` (напр. `project:a=project:b`) |

Формат — JSONL: первая строка заголовок (`format`/`version`/`exported_at`/`db`), дальше по
одной записи памяти на строку (`id`, `kind`, `scope`, `content`, `summary`, `importance`, все
таймстампы, `superseded_by`, `source`, `tags`, `links`) — стримится, диффается, `grep`ается.
Векторы **не экспортируются** — это производные данные; после импорта их досчитывает
фоновый reindex при следующем запуске `memoryd` (пустая `embed_meta` новой БД → полный
reindex). Тумстоуны (мягко забытые записи) экспортируются и импортируются как есть — история
переносится вместе с фактами. Импорт восстанавливает id и все таймстампы в точности (не через
обычный write-путь — без дедупликации/переклассификации): конфликт id по умолчанию
пропускается со счётчиком, `-overwrite` заменяет; ссылка на id, которого нет в целевом
хранилище, — предупреждение и пропуск ребра, остальной импорт продолжается. Итоговая строка:
`imported N, skipped M, links K (dropped L)`.

Типичный сценарий бэкапа/переноса:

```bash
memoryd export -o backup.jsonl                       # весь инстанс в файл
memoryd import -db ~/new-machine/memory.db backup.jsonl
```

MCP-инструменты, которые видит агент: `memory_save`, `memory_recall`, `memory_update`,
`memory_forget` — набор маленький намеренно, подробности по формату аргументов в
`DESIGN.md` §12.

## Конфигурация

TOML-файл, секции `[store] [embedder] [reasoner] [recall] [maint] [scope]`. Пример со
всеми полями и комментариями — `config.example.toml`. Если конфиг не передан или в нём
чего-то не хватает, действуют дефолты из `internal/config.Default()` (эквивалент этапа
MVP: только SQLite+FTS5, без вектора и без LLM).

Коротко по секциям:

- `[store]` — путь к файлу SQLite.
- `[embedder]` — `noop | ollama | openai`; при `ollama` `dim` определяется автоматически
  пробным эмбеддингом при старте, руками не задаётся.
- `[reasoner]` — `noop | deepseek`; ключ **не в этом файле**.
- `[recall]` — дефолтный токен-бюджет брифа и веса ранжирования (relevance/importance/recency/access).
- `[maint]` — интервалы фоновых джобов (decay, consolidation).
- `[scope]` — имя текущего проекта (мультипроектность через общий файл БД + scope) и
  список пространств, всегда добавляемых к recall (по умолчанию `["user:*"]`).

Ключ DeepSeek — только `DEEPSEEK_API_KEY` в окружении или `.env` рядом с конфигом
(`KEY=VALUE`, поддерживает `#`-комментарии и кавычки). Shell-env приоритетнее `.env`.
В TOML-конфиг ключ никогда не пишется.

<p align="center"><sub>Исходник для правок — <a href="docs/architecture.drawio">docs/architecture.drawio</a> (открывается в <a href="https://app.diagrams.net">draw.io</a>)</sub></p>

- **Три поверхности доступа** — один бинарь `memoryd`, одна доменная логика: MCP over
  stdio для агентов (`memory_save`/`recall`/`update`/`forget`), CLI и ambient-хуки
  харнесса для терминала (`recall`/`save`/`hook`/`doctor`/`export`/`import`) и web-морда
  для человека (`memoryd web` — поиск, карточка, правка метаданных).
- **Store** — единый SQLite-файл: таблица `memories` (+`expires_at`, TTL), FTS5-индекс
  (со стемминг-колонкой для русской морфологии), опциональная vec-таблица (`sqlite-vec`),
  миграции через `PRAGMA user_version`; всё за интерфейсом `Store`.
- **Writer** (`internal/memory/write`) — приём факта: дедуп по scope, обновление или
  пометка `superseded_by` вместо DELETE, типизированные связи (`rel`), TTL.
- **Recall** (`internal/memory/recall`) — гибридный поиск (FTS5 + вектор) → слияние через
  Reciprocal Rank Fusion → ранжирование по relevance/importance/свежести/частоте обращения
  → сборка Markdown-брифа под токен-бюджет; фильтры по scope/kind/тегам/датам, explain-трасса.
- **Maint** (`internal/memory/maint`) — фоновые джобы по расписанию: expire-sweep (TTL),
  decay episodic-записей, консолидация episodic→semantic через Reasoner, dedup-sweep,
  reindex при смене Embedder-модели.
- **Embedder / Reasoner** — за интерфейсами, оба опциональны и деградируют вместо падения:
  Embedder (ollama или openai-совместимый) недоступен → recall работает на чистом FTS5,
  без DeepSeek — без суммаризации и консолидации.

Подробности — модель данных, интерфейсы, write/read path, roadmap — в `DESIGN.md`.

## Разработка

```sh
make build   # CGO_ENABLED=1 go build -tags sqlite_fts5 ./...
make test    # CGO_ENABLED=1 go test -tags sqlite_fts5 ./...
make run     # CGO_ENABLED=1 go run -tags sqlite_fts5 ./cmd/memoryd — MCP-сервер из исходников
make web     # CGO_ENABLED=1 go run -tags sqlite_fts5 ./cmd/memoryd web — web-морда из исходников
```

Тег `sqlite_fts5` и `CGO_ENABLED=1` обязательны везде — без них FTS5 не соберётся.

Код:

- `cmd/memoryd` — точка входа: сервер, `init`, `web`.
- `internal/memory` — домен: `types.go`, `store/` (SQLite), `embed/` (Embedder), `reason/`
  (Reasoner), `write/` (ingest), `recall/` (поиск и бриф), `maint/` (фоновые джобы).
- `internal/mcp` — регистрация MCP-инструментов и роутинг.
- `internal/config` — загрузка TOML/env.

Архитектурные решения и границы пакетов — в `DESIGN.md`, читай перед изменениями.
