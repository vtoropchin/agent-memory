# AgentMemory

Система долговременной памяти для ИИ-агентов: MCP-сервер `memo` + CLI. Go, один бинарь.

Источник истины по замыслу, модели данных и границам пакетов — [`DESIGN.md`](DESIGN.md)
(§4 модель, §5 пакеты, §6 интерфейсы, §15 принципы). Реализация обязана ему соответствовать;
отклонение сначала обсуждается и вносится в `DESIGN.md`, а не делается молча в коде.

## Архитектура

Дисциплина: чистая архитектура (набор скилов `.claude/skills/`, точка входа — `/dev`).

**Соответствия понятий в этом проекте**

| Понятие | Реализация здесь |
|---|---|
| Компонент | Go-пакет; единица развёртывания — один бинарь `cmd/memo` |
| Порт | `interface`: `store.Store`, `embed.Embedder`, `reason.Reasoner` |
| Структура через границу | `struct` из `internal/memory`: `Memory`, `Query`, `Brief`, `Candidate` |
| Composition root (`Main`) | `cmd/memo/main.go` — `main()` и фабрики `newEmbedder`, `newReasoner`; сборка графа и деградация до `noop` живут только здесь |
| Ограничение видимости | `internal/`, регистр имени; экспортируется минимум |
| Подмена в тестах | своя реализация интерфейса, переданная полем/аргументом (`fakeEmbedder` в `write_test.go`, `recall_test.go`, `consolidate_test.go`; `fakeLocal`/`fakeHub` в `sync/fake_test.go`); моки-библиотеки не используются |
| Изоляция времени и случайности | порт времени есть в `write` и `recall`: поле `now func() int64` + опция `WithNow` (по умолчанию `time.Now().Unix()`). В `maint` (`decay.go`, `expire.go`, `consolidate.go`) `time.Now()` зовётся напрямую — так делать в новом коде не надо, время передавать полем (образец — `scheduler.go`: поле `now func() int64`). Идентификаторы — `oklog/ulid` |

**Структура**

- Сущности: `internal/memory` (`types.go`) — только стандартная библиотека, ноль внешних зависимостей.
- Варианты использования: `internal/memory/write` (ingest, дедуп, связывание), `internal/memory/recall`
  (гибридный поиск RRF + ранжирование + сборка брифа), `internal/memory/maint`
  (decay, consolidate, reindex, dedup-sweep, планировщик), `internal/memory/board`
  (kanban-доска: `Build`, карточка задачи `Describe`; свои порты `Source`/`DetailSource`,
  `store` не импортирует), `internal/memory/sync` (синхронизация проекта с общей базой: push/pull,
  LWW; свои порты `Local`/`Shared`/`Dialer`, `store` не импортирует — адаптеры в `store` импортируют
  его под псевдонимом `memsync`). У `board` и `sync` ноль нарушений правила зависимостей.
- Порты объявлены в `store`, `embed`, `reason`; там же лежат реализации — см. «Известное нарушение».
- Адаптеры: `store/sqlite.go`, `store/postgres*.go`, `embed/ollama.go`, `embed/openai.go`,
  `reason/openai.go` (OpenAI-совместимый chat: DeepSeek, CLIProxyAPI), `internal/mcp` (регистрация tools и JSON-схемы), `cmd/memo/web.go`.
- Загрузка конфига: `internal/config` (TOML/env).
- Composition root: `cmd/memo`; cobra и huh — зависимости CLI-инсталлятора, в ядро не попадают.
- Циклы между пакетами запрещает компилятор Go — отдельная проверка ADP не нужна.

**Известное нарушение (базовая линия, не норма)**

Порт `store.Store` объявлен в одном пакете с реализациями (`sqlite.go`, `postgres*.go`), поэтому
`write`, `recall` и `maint` компонуются с драйверами БД, хотя пользуются только интерфейсом.
Лечится вынесением порта из пакета реализаций. До тех пор базовая линия зафиксирована тестом и
не должна расти.

**Проверка**

- Сборка: `make build` (`CGO_ENABLED=1 go build -tags sqlite_fts5 ./...`); бинарь для догфудинга: `make bin/memo`.
- Тесты: `make test` (`CGO_ENABLED=1 go test -tags sqlite_fts5 ./...`). Отдельного линтера и CI в проекте нет;
  форматирование — `gofmt`.
- Правило зависимостей: `CGO_ENABLED=1 go test -tags sqlite_fts5 -run TestDependencyRule ./internal/memory/`
  (`internal/memory/arch_test.go`, входит в обычный `make test`). Базовая линия нарушений: **5** для каждого
  из `write`, `recall`, `maint`; **0** для `internal/memory`, `internal/memory/board` и `internal/memory/sync`. Тест падает и при росте, и при снижении —
  снижение требует опустить линию в `baseline`.
- Тесты ядра идут без сети и внешних сервисов (SQLite во временных файлах); прогон
  `./internal/memory/...` — около 2,5 с, это и есть целевое время.
- Что метрика **не** считает: сторонние модули считаются, стандартная библиотека — нет. Адаптеры
  на stdlib (`embed/ollama.go`, `embed/openai.go`, `reason/openai.go` — `net/http`) в число не
  попадают, хотя лежат рядом с портами. Ноль по метрике здесь не означает «границы чисты»;
  условие пересмотра — первый SDK в `embed` или `reason`.

**Идиомы языка (не считать нарушениями)**

- Интерфейс объявляет **потребитель**, а не реализация; порт, объявленный прямо в пакете варианта
  использования, — норма Go. Отдельный пакет `ports/` не требуется.
- Структурная типизация: у адаптера нет `implements`; `var _ Embedder = (*Noop)(nil)` — проверка
  на этапе компиляции, а не связывание слоёв.
- `New` возвращает `*Recaller`/`*Writer`, а не интерфейс («accept interfaces, return structs») —
  DIP это не нарушает.
- Тесты лежат рядом с кодом и в том же пакете, включая проверку неэкспортируемых функций, —
  идиома, а не пробитая граница. Отдельный каталог `test/` не нужен.
- Функциональные опции (`Option`, `WithNow`) — законная инъекция зависимостей.
- Заглушки `Noop` рядом с портом в `embed`/`reason` — не повтор истории со `store`: они на
  стандартной библиотеке и ничего не тянут.

**Отложенные решения**

Обязаны оставаться заменяемыми без правки ядра: хранилище (SQLite ↔ PostgreSQL), провайдер
эмбеддингов (noop / ollama / openai), провайдер reasoner (DeepSeek / CLIProxyAPI), транспорт (MCP stdio, CLI,
web-морда). Недоступность вектора или LLM — деградация, а не падение (`DESIGN.md` §15).
Конкретные отложенные решения, компромиссы и проведённые границы хранятся в памяти проекта
(`memo`, scope `project:AgentMemory`), а не в этом файле: recall в начале задачи, запись по ходу.

## Код

- Комментарии и сообщения об ошибках — на русском, как в существующем коде.
- Ошибки оборачивать с контекстом: `fmt.Errorf("...: %w", err)`; `context.Context` — первым аргументом;
  паник в библиотечном коде нет.
- Валидация только на границах (вход MCP, внешние API), не в каждом слое.
- Секреты (`DEEPSEEK_API_KEY`, `CLIPROXY_API_KEY`, `OPENAI_API_KEY`, `MEMO_POSTGRES_PASSWORD`) — только из env/`.env`;
  в код, логи и память не попадают.
- Не выходить за рамки задачи: без «заодно отрефакторю», абстракций на будущее и feature-флагов.

## Память проекта

Проект догфудит сам себя: память живёт в собственном `memo`, подключённом MCP-сервером
(`.mcp.json` + `agentmemory.toml`, scope `project:AgentMemory`). Протокол — скил `memo`.
Каталог `.claude/memory/` — архив мигрированной файловой памяти, новые факты туда не пишутся.
