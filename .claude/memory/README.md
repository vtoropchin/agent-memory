Это была временная файловая память проекта, которую вёл оркестратор `/dev`. Структура
намеренно повторяет модель **приложения** (см. `DESIGN.md`): один факт = один файл
с frontmatter — поэтому перенос в memoryd задачей 5.1 прошёл почти 1:1.

## Формат файла

```markdown
---
name: <короткий-kebab-slug>
kind: project | decision | reference    # аналог memories.kind
importance: 1..5
tags: [tag1, tag2]
---

<сам факт: 1-3 предложения, атомарно>

**Почему:** <обоснование>
**Как применять:** <как это влияет на работу>

Связано: [[другой-slug]]
```

- `kind`:
  - `decision` — принятое архитектурное/процессное решение (why + как применять);
  - `project` — состояние/прогресс/цель, не выводимые из кода и git;
  - `reference` — указатель на внешний ресурс (URL, тикет).
- Ссылки между записями — `[[slug]]` (может указывать на ещё не созданную запись).

## Индекс

Один-строчные указатели на все записи — в `MEMORY.md` (загружается в контекст первым).
При создании записи добавляй строку туда; при удалении — убирай.

## Правила

- Перед задачей `/dev` читает `MEMORY.md` и релевантные записи.
- После задачи `/dev` дописывает новые решения/прогресс, обновляет устаревшее, удаляет
  ошибочное.
- Не дублируй то, что и так есть в коде/`DESIGN.md`/git. Обновляй существующую запись, а не
  плоди дубли.
- Секреты не хранить.
