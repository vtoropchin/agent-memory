Правило процесса (указание пользователя, 2026-07-11): **каждая задача разработки — отдельный
.md-файл в `tasks/`**, самодостаточный для выполнения младшей моделью: контекст, шаги,
границы («за рамки не выходить»), критерий приёмки. Индекс со статусами — `tasks/README.md`.

**Как применять:** оркестратор `/dev` при декомпозиции сначала пишет файл задачи, затем
делегирует агенту `go-developer` ссылкой на файл (агент читает файл + общие требования из
tasks/README.md). После выполнения агент обновляет статус в файле задачи; статус в индексе
обновляет оркестратор. Нумерация задач — по этапам DESIGN.md §14 (2.1, 3.2, …).

**Дополнение (2026-07-11): каждая задача выполняется в отдельной новой сессии** — не
пачкой в одной длинной. Сессия берёт один файл tasks/*.md, выполняет, финализирует,
фиксирует память и завершается.
