Грабли и тех-долг Этапа 1 (MVP), выявленные при реализации/финализации.

**Сборка — обязательные флаги.** Драйвер `mattn/go-sqlite3` требует CGO и build-тег для FTS5:
`CGO_ENABLED=1 go build -tags sqlite_fts5 ./...` (то же для `go test`). Без тега FTS5 недоступна.
Флаги зашиты в `Makefile` (`build`/`test`/`run`).

**Решения, отступающие от иллюстративной схемы/дизайна (приемлемы для MVP, задокументированы в коде):**
- `memories_fts` сделана **self-contained**, а не external-content (`content='memories'`): колонка
  `tags` — денормализованный агрегат, синхронизация триггерами по rowid проще и надёжнее.
  Интерфейс `Store` не тронут.
- **Висячие ссылки не поддержаны** (§7.3 их допускает, но схема §4 даёт FK `links.dst→memories(id)`).
  `write` линкует только существующие id, несуществующие молча пропускает (не роняет `Save`).
  Тех-долг: на будущих этапах либо снять FK, либо завести таблицу отложенных ссылок.
- **`memory_forget` = тумстоун** через `Supersede(id, id)` (self-supersede): запись выпадает из
  recall/SearchLexical, но строка и история целы. DELETE не используется (§4/§15).

**Известное ограничение recall Этапа 1 (НЕ баг):** чистый FTS5 **без стемминга** не ловит
русскую морфологию — запрос «собирать/тестировать» не матчит сохранённое «Сборка/тесты».
Ровно это чинит Этап 3 (эмбеддинги `bge-m3` мультиязычные). Пока recall хорош на точных
токенах/именах/ключах, слабее — на перефразировках. Учитывать при догфудинге (Этап 5).

**Нормализация importance едина** в `write` (`clampImportance`: 0→3, clamp [1,5]); `Save` и
`Update` ведут себя одинаково (после фикса рассинхрона на финализации). `mcp/update`/`forget` —
тонкие обёртки, к `store` напрямую не ходят.
