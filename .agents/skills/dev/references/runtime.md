# Runtime: роли, модели и ревью в разных клиентах

Справочник к `SKILL.md`. Цикл `dev` одинаков в любом кодинг-агенте (Claude Code, DeepSeek
Harness, Hermes Agent и др.); различается только то, **чем** запускаются роли и ревью.
Опирайтесь на инструменты, реально доступные в текущей сессии, а не на имена из памяти.
Имена инструментов конкретного клиента — в адаптере рядом (`runtime-<клиент>.md`); для
клиента без адаптера сопоставьте возможности ниже с его фактическими инструментами сами.

## Возможности клиента

| Возможность | Что даёт циклу | Если нет |
|---|---|---|
| Субагент со свежим контекстом | роли и ревью без рассуждений основной модели | роль выполняется в основном контексте отдельным проходом (см. ниже) |
| Именованные агенты клиента | роль запускается по имени; их создаёт `/adapt` из файлов ролей | общий субагент с файлом роли в промпте |
| Продолжение того же субагента | правки по находкам с контекстом исполнителя | новый запуск: ТЗ + прежний отчёт + находки |
| Выбор модели субагента | режим делегирования (`implementer` на сильной модели для кода) | режим «сама» |
| Встроенные команды ревью кода/безопасности | ревью на баги фазы 5а | субагент-ревьюер по процедуре ниже |
| Поисковый субагент | разовый поиск по коду | обычный поиск по файлам |
| MCP `memo` | память решений (скил `memo`) | решения проговариваются в отчёте |
| Документация библиотек (`context7` или аналог) | API адаптеров не по памяти | официальная документация |

Fork всей беседы основной модели — не свежий контекст: ревьюер видит рассуждения автора и
теряет независимость. Для ролей и ревью используйте свежий запуск.

## Запуск роли

Роли — файлы `agents/<роль>.md` этого каталога. Заголовок файла нейтрален:

| Поле | Значения | Что значит для запуска |
|---|---|---|
| `access` | `read-only` | роль ничего не пишет: ни код, ни документы |
| | `design-docs` | пишет только проектные документы, если они названы в задании; код не трогает |
| | `code` | пишет только файлы, перечисленные в ТЗ |
| `memo` | `recall` / `read-write` | только чтение памяти / чтение и запись решений |
| `model` | `inherit` | модель сессии |
| | `strong-coding` | самая сильная доступная модель для кода; нельзя выбрать — модель сессии |

Порядок выбора способа:

1. **Именованный агент клиента** с тем же именем есть (его ставит `/adapt`) — запустить его
   с заданием.
2. **Общий субагент со свежим контекстом** — промпт: «Ты выполняешь роль `<роль>`. Прочитай
   целиком `<путь к dev>/references/agents/<роль>.md` и следуй ему. Ограничения доступа:
   `<access>`. Задание: …». Ограничения `access` и `memo` передаются текстом и, если клиент
   позволяет, настройками запуска.
3. **Субагентов нет** — прочитать файл роли и выполнить её в основном контексте отдельным
   проходом. В отчёте отметить: «роль `<роль>` выполнена без свежего контекста». Для ревью
   это снижает независимость, но ревью не пропускается.

Под назначением `orchestrate` (brief v3) роль запускается с `memo: recall` независимо от
заголовка: решения и предложения записей она возвращает в отчёте, а dev-lead переносит их в
`memo_proposals`. Запуски занимают слоты пула `bounded_subagents`.

Задание роли самодостаточно: субагент видит файлы проекта, но не разговор и не авто-recall
памяти (`SKILL.md`, правила делегирования).

## Модель сессии и режим делегирования

Делегирование выбирается, если сессия идёт на модели верхнего класса и клиент позволяет
запустить `implementer` на сильной модели для кода. Модель сессии берётся из сведений, которые
клиент даёт о себе (системная информация, команда статуса). Не удалось установить — режим
«сама». Идентификатор модели не угадывается по памяти: только из списка, доступного клиенту.

## Ревью на баги и безопасности без встроенных команд

Если у клиента нет встроенного ревью, запустите субагента со свежим контекстом:

> Проведи ревью на ошибки поведения для изменений `<цель: коммиты ветки сверх upstream +
> незакоммиченное, либо файлы шага>` на уровне `<low|medium|high>`. Ничего не исправляй.
> Для каждой находки: `файл:строка`, сценарий сбоя (вход → неверный результат/падение),
> уверенность. Без сценария находку не выдавай. Отдельно пометь ошибки в строках, которые
> diff не менял.

- `low` — только явные ошибки с высокой уверенностью, немного находок;
- `medium` — плюс граничные случаи и обработка ошибок изменённого кода;
- `high` — тщательно, включая стыки с вызывающим кодом, конкурентность и данные.

Нет ни встроенного ревью, ни субагентов — тот же промпт выполняется в основном контексте
отдельным проходом по diff, без правок по ходу; в строке «Ревью» отчёта — «без свежего
контекста». Ревью не пропускается.

Ревью безопасности — тот же запуск с фокусом на авторизацию, инъекции, секреты, валидацию
входа, криптографию и права доступа. Находки разбираются по классам фазы 5а `SKILL.md`.
