# Редизайн веб-морды `memo web` — спецификация по принятому макету

**Макет:** [memo-web-prototype.html](memo-web-prototype.html) — один самодостаточный HTML,
открывается двойным кликом; внизу файла — HTML-комментарий с заметками для реализации.
**Принят:** 2026-09-22. **Реализация:** Этап 16 (DESIGN.md §14), в отдельных сессиях через `/dev`.

Этот документ — источник истины по поведению и виду новой морды. Макет иллюстрирует его;
при расхождении первичен документ, макет правится.

## 1. Что не так с текущей мордой (ранжировано)

1. Нет обзора: первый экран — счётчики + стена чипов-scope + список всех записей всех проектов.
2. Scope фильтруется чекбоксами (20+ штук) в списке и отдельным селектом на доске — два механизма.
3. Состояние провайдеров (эмбеддер/reasoner) невидимо; деградация всплывает только после поиска.
4. Карточка записи — модалка в три экрана, связи как голые ULID.
5. Список — карточки одинаковой массы, нет иерархии.
6. Доска: drag&drop без клавиатурной альтернативы, блокировка только цветом, свимлейны выключены.
7. «Удалить (в архив)» без подтверждения и объяснения последствий.
8. Одна палитра, невидимый фокус, мелкие контролы.

Все восемь пунктов закрыты макетом; ничего не отложено.

## 2. Экраны

Три раздела в шапке: **Обзор · Память · Доска**. Справа в шапке — единственный на всё
приложение **селект scope** (`все scope` / список из `stats.byScope`, домашний помечен).
Он же — параметр `scope` для всех трёх экранов. Состояние (раздел, scope, фильтры,
открытая запись) — в URL-хэше, как сейчас.

### 2.1 Обзор (`#/`)
- Заголовок: `N записей в <scope>` · `M в архиве` · `обновлено <относительно>`.
- Плашка деградации, если эмбеддер недоступен (текст — см. §5).
- Пять счётчиков по видам (клик → Память с фильтром вида).
- «Добавлено за 7 дней» — до 10 записей: вид · заголовок · когда. Пусто → текст-приглашение.
- «На доске» — задачи в `doing`, затем `review`/`testing`, затем заблокированные:
  стадия · заголовок (+ вторая строка `заблокирована · ждёт: <блокер>`) · ветка · когда.
- Правая колонка: **Сервисы** (хранилище, эмбеддер, reasoner, фоновые джобы — точка
  ok/off, одна строка пояснения), **Истекает скоро** (записи с `expiresAt` ближе 14 дней),
  **Scope** (живые записи по scope, клик → выбрать scope).
- Списки обзора: колонка меток фиксированной ширины (96 px), текст с одной вертикали,
  даты справа.

### 2.2 Память (`#/memory`)
- Поиск (`/` фокусирует поле) + переключатель «по смыслу | по словам» (radiogroup).
- Фильтр вида — пять чипов-чекбоксов (multiselect); «с архивом»; справа — счётчик
  активных фильтров и **«Сбросить всё»** одной кнопкой (снимает вид, архив, запрос и scope).
- Плашка деградации при `vector:false` и режиме «по смыслу».
- Строка результата: цветная левая кромка вида · вид + scope (+ стадия для задач) ·
  заголовок серифом (summary или content, 2 строки) · теги · важность (5 сегментов) ·
  когда · источник кандидата («по словам» / «слова + смысл»). Архивная — зачёркнута
  с чипом «в архиве · заменена». Совпадения запроса подсвечены.
- Состояния: пусто в scope, нет результатов (разный текст при деградации), ошибка API.

### 2.3 Запись (панель поверх списка/доски)
- Ширина ≥ 1200 px — по центру (720 px, отступы 40 px, скругление, тень); уже — панель
  у правого края во всю высоту. Фон под панелью `inert`; Esc закрывает, фокус возвращается.
- Шапка: вид · scope · «Закрыть». Для задачи — ещё «К доске».
- Тело: важность (кликабельные сегменты → PATCH) · «создана»; summary (сериф, крупнее);
  полный текст (сериф, `pre-wrap`); **Теги** (чипы с ×, поле «+ тег…», Enter → PATCH);
  **Связи** — исходящие `→ заменяет / связано / следствие / часть / заблокирована`,
  входящие `← заменена / связано / причина / включает / блокирует`, у цели — вид и
  заголовок, клик открывает её в той же панели; **Похожие по вектору** с расстоянием
  (или «нет данных — эмбеддер недоступен»); **Служебное** (id, даты, читалась N раз,
  источник, вектор/в очереди).
- Архивная запись: плашка «В архиве с … — заменена записью <…>», без правки.
- TTL: плашка «Истекает через … — выпадет из recall и уйдёт в архив».
- Футер: **Изменить** (инлайн-правка summary/текста → Сохранить/Отменить) · **Забыть…**
  → инлайн-подтверждение (см. §5) → тост.

### 2.4 Доска (`#/board`)
- Панель: тип · «Внутри» (эпик/история) · тег · «дорожки по родителю» (вкл. по
  умолчанию) · счётчик задач и заблокированных · «Сбросить».
- Подсказка одной строкой: перетащить или открыть и сменить стадию; с клавиатуры —
  Enter на карточке, затем поле «Стадия».
- Семь колонок фиксированного порядка; `done` — 30 последних + «показать ещё».
- Карточка: тип · «заблокирована» (красным, title с блокерами) · важность · заголовок
  (кнопка) · прогресс `done/total` у эпика/истории · ветка (моно) · когда ·
  `select` «Переместить в стадию» (виден при hover/focus — клавиатурная альтернатива
  DnD). Заблокированная — штриховка фона. Эпик — тёмная кромка, история — серая,
  задача — фиолетовая.
- DnD: подсветка целевой колонки, оптимистичный перенос, 409 → откат + тост с блокерами.

### 2.5 Задача (та же панель)
- Заголовок (крупно, sans); плашка «Заблокирована. Дальше «к работе» не перевести,
  пока не закрыта: <блокер> (стадия)».
- Поля 2×2: Стадия · Тип · Ветка · Процесс (каждое → PATCH сразу).
- Приоритет (сегменты) · Описание (сериф) · **Входит в** (родитель + «Отвязать» + пикер)
  · **Дочерние** (прогресс-бар + список) · **Блокировки** (ждёт: … «Снять»; блокирует: …;
  пикер «Добавить блокер») · Связано · Теги · Служебное.

## 3. Визуальная система (design tokens → `tailwind.input.css`)

Токены объявлены в `:root` макета — переносить как есть.

- Поверхности: `--bg #F5F5F2`, `--surface #FFFFFF`, `--surface-2 #ECECE8`, `--surface-3 #E3E3DE`.
- Текст: `--ink #1C1F23`, `--ink-2 #464B53`, `--ink-3 #676C75` (≥ 4.5:1 на surface).
- Линии: `--line #DADBD6`, `--line-strong #8A8D87` (≥ 3:1 — границы контролов).
- Акцент: `--accent #2E5BDA` / `--accent-soft #E6ECFB`; `--danger #B4231F`, `--warn #7A5300`,
  `--ok #1F6E3A` + мягкие фоны.
- Виды: `semantic #2F5FB3`, `episodic #8A5A10`, `procedural #187066`, `debt #B3402B`,
  `task #6A4FBF` — цветная кромка 3 px + квадратик 8 px + слово; не заливка чипа.
- Тёмная тема: те же токены под `prefers-color-scheme: dark` (значения в макете).
- Шрифты: интерфейс — системный sans; **содержание памяти (summary, content, заголовок
  в списке) — сериф** (`Iowan Old Style, Charter, Palatino, Georgia`); id/ветки — mono.
- Важность — 5 сегментов 6×10 px, не звёзды. Даты — относительные («2 ч назад»),
  старше 30 дней — дата без времени; полные метки — в «Служебном».
- Без градиентов, теней на карточках (тень только у центрированной панели), эмодзи,
  иконок в заголовках.

## 4. Доступность (проверено на макете)

- Контраст текста ≥ 4.5:1 в обеих темах, границ контролов ≥ 3:1.
- `:focus-visible` кольцо на всём интерактивном; строки списка — кнопка внутри
  `article`, не `div[tabindex]`.
- Панель: `role=dialog aria-modal`, `inert` на фоне, Esc, возврат фокуса.
- DnD дублируется `select` в карточке и полем «Стадия» в панели — тот же `PATCH {status}`.
- Skip link, `<h1>` в шапке, `aria-live` только на тостах и счётчике результатов.
- Осознанно не сделано: цели 44 px (десктопный инструмент).

## 5. Тексты (ux-copy, русский)

- Деградация (обзор): **Поиск по смыслу недоступен.** Эмбеддер ollama/bge-m3 не отвечает —
  поиск работает только по словам, новые записи копят очередь на эмбеддинг. Сохранение и
  доска работают как обычно.
- Деградация (память): **Поиск только по словам.** Эмбеддер не отвечает, поэтому запрос
  не эмбеддится и перефразировки не найдутся — ищи точными терминами. Как только ollama
  вернётся, режим «по смыслу» включится сам.
- Ошибка API: **Сервер памяти не отвечает.** Запрос к `/api/…` завершился ошибкой
  соединения. Проверь, что `memo web` запущен на localhost:7070. [Повторить]
- Нет результатов: По запросу «…» ничего не нашлось. Проверь фильтры вида и scope — они
  сужают выдачу. Или переформулируй: поиск по смыслу находит и перефразировки. [Сбросить фильтры]
- Пусто: В <scope> пока ничего нет. Агент пишет сюда по ходу задач через `memory_save`…
- Подтверждение: **Забыть эту запись?** Она выпадет из recall агента и уйдёт в архив; текст
  и N связей сохранятся, восстановить можно через `memory_update`. [Забыть] [Оставить]
  (для задачи с детьми — «K дочерних задач останутся без родителя»).
- Тосты: «Забыта: «…» — в архиве», «Перенесена в «ревью»», «Не переведена: «…»
  заблокирована — <блокеры>», «Тег «x» добавлен/снят», «Важность 4 из 5», «Сохранено».

## 6. Что ложится на существующий API (без изменений)

- Обзор: `GET /api/stats` (byKind, byScope, homeScope); «Добавлено за 7 дней» —
  `GET /api/memories?scope&limit=10` (ULID сортирует по времени; отсечь по createdAt);
  «На доске» — `GET /api/board?scope` и фильтр колонок на клиенте.
- Память: `GET /api/memories?scope&kind&superseded=1&limit&offset`; поиск —
  `GET /api/search?q&mode&kind&scope`; плашка — `vector:false`; подпись источника — `source`.
- Запись: `GET /api/memories/{id}`; важность/теги — `PATCH {importance}` / `{tags}`;
  «Забыть» — `DELETE`; входящие связи — из `neighbors` (у DTO только исходящие `links`).
- Задача: `PATCH {status|type|branch|workflow|links|unlinks}`; пикеры —
  `GET /api/search?q&mode=lexical&kind=task`; 409 `{error, blockers}` → тост + откат.

## 7. Что требует новых полей/решений (в порядке реализации)

1. **`GET /api/stats` → `providers` и `jobs`**: `{store:{driver,dsn-без-пароля,schema},
   embedder:{provider,model,dim,available,pending}, reasoner:{provider,model,available},
   jobs:{lastRunAt}}` — для панели «Сервисы» и плашки деградации до первого поиска.
   Композиция знает провайдеров (`newEmbedder`/`newReasoner` в `cmd/memo`), `pending` —
   `len(ListMissingVectors)` или отдельный count. Это задача бэкенда, выполнять первой.
2. **Правка `summary`/`content` из браузера** («Изменить») противоречит инварианту
   DESIGN §12 («content/summary из браузера не редактируются никогда»). Макет принят
   вместе с кнопкой «Изменить» (2026-09-22), поэтому по умолчанию **инвариант снимается**:
   PATCH принимает `content`/`summary` → `write.UpdateInput{Content, Summary}`
   (переэмбеддинг уже делает `Writer.Update`), DESIGN §12 правится в той же задаче.
   Это единственное отклонение от DESIGN — подтвердить явно на этапе design в `/dev`
   до кода. `kind`/`scope`/создание/hard DELETE — по-прежнему из браузера недоступны.
3. **«Истекает скоро»** — параметр `expiresBefore=<unix>` в `GET /api/memories`
   (фильтр `expires_at IS NOT NULL AND expires_at < ?`); без него секцию не показывать.
4. Прочее (`accessCount`, `embedding.embedded`, `semanticNeighbors.distance`) — уже в DTO.

## 8. Границы реализации

- Стек не меняется: vanilla JS + Tailwind, бандл в бинаре, без CDN и сторонних библиотек
  (решение Этапа 6). Роутинг — hash, как сейчас.
- Доменной логики на фронте нет: рисуется ответ сервера, ошибки маппятся в тексты.
- Старый фронт заменяется, не дописывается: `index.html`/`app.js` переписываются под новую
  структуру; тесты `web_test.go` на статику и API остаются зелёными.
- Нарезка на задачи — в `tasks/16.x-*.md` по конвенции проекта (`/dev` делает сам).

## 9. Критерий приёмки этапа

Пять сценариев ТЗ проходятся в реальном приложении на живой базе (PostgreSQL и SQLite):
1. открыл — за 5 секунд вижу, сколько записей, что добавилось, что в doing, доступен ли эмбеддер;
2. нашёл факт по смыслу, открыл, прочитал, перешёл по связи;
3. поправил текст/важность/теги или забыл запись, не покидая списка, с подтверждением;
4. доска: стадии, карточка, блокировки, part_of; перенос мышью и с клавиатуры;
5. фильтр scope и вида виден и сбрасывается одной кнопкой.
Плюс: тёмная тема, контраст AA, клавиатурная навигация, чек-лист §4.
